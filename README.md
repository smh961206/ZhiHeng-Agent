# 知衡 · 价值投资研究 Agent

React + Node.js。将V4.7 单一规则知识库转为六类研究任务、证据检索、估值工具和模型审计。只使用自动抓取的数据，不预置研究结果。

Agent 可在研究过程中按主题补读已确认 A 股标的的官方公告（产销、股本月报、分红、回购与回报政策），新增正文进入同一资料库、检索、原页读取与审计链。每项任务最多 6 次、每次最多 3 份，保留部分失败、归档复用及覆盖限制。研发与再投资工具核算同期研发资本化和 Quick FCF；估值快照区分股类权益等值与实际市值、归母与普通股权益。模型对照只引用已完成计算的调用编号，不混用币种/股数，不合并压力测试与主模型。详情页根据实际返回显示查证记录，并支持运行中、取消或失败任务导出已保存的公开执行记录。原图仍由配置的 Vision 服务读取，研究与复核仍使用平台模型服务；这些能力不需要在产品中加入案例页面。

SKILL 原始版本备份与合并、升级关系见 [版本归档](knowledge/versions/README.md)，包含 V2.1、V2.2、V3、V4.0、V4.1、V4.1.1、V4.2 、V4.3 、V4.4 、V4.5 、V4.6 和当前最新 V4.7。

知识模块自动备份（索引、目录和全部模块）：`pnpm dev` 运行时检测更新，`pnpm start` 和 `pnpm build` 执行前也会备份；相同内容自动去重，同版本修订保留独立快照。修改原文前后可运行 `pnpm knowledge:backup`，备份位于 `knowledge/versions/auto/`。

## 启动

Linux Docker 一键部署、代码更新、数据库版本迁移与备份回滚见 [部署文档](DEPLOY.md)。配置 `.env.production` 后执行 `bash deploy.sh up`，后续执行 `bash deploy.sh upgrade`。

要求 Node.js **22.13+**、pnpm、已启动的 Docker Desktop（Linux 容器）。

```powershell
pnpm install
Copy-Item .env.example .env
pnpm db:up
# 在.env配置模型后运行
pnpm dev
```

开发页面 `http://127.0.0.1:5173`，后端 `http://127.0.0.1:3001`。

服务重启中断研究后，详情页“重试研究”会优先恢复最近保存的执行进度，复用已采集资料与已完成工具结果。新的任务会保存模型轮次与工具调用检查点；旧记录可依据已完成的采集阶段和实际工具记录恢复上下文。未完整返回的请求需要重新发起；资料采集尚未完成、没有可用进度的任务仍会从头开始。续跑保留原行情时点，最终报告仍须通过完整复核。

```powershell
pnpm build
pnpm start
```

构建后统一使用 `http://127.0.0.1:3001`。Windows也可运行 `./start.ps1`，优先系统Node，找不到时使用本机已有Codex Node运行时。本应用仅监听本机，无多用户鉴权，不应直接暴露到公网。

必须填写 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`。模型需支持Chat Completions工具调用及按协议返回JSON。密钥只在后端读取；问题、组合信息、选用的历史研究快照和相关财报片段会发送给配置的模型服务。未配置模型直接报错。可设置 `SEC_USER_AGENT=应用名 真实联系邮箱` 以符合SEC来源访问要求。

## 使用与数据源

### 从输入到交付的操作衔接

研究路径默认在输入停顿 800 毫秒后请求后端 `/api/research/path`，仅发送问题文本。后端使用配置的模型理解主要诉求、否定和引用，并返回六类路径之一与简短理由；可用 `LLM_ROUTER_MODEL` 单独指定分类模型，留空复用 `LLM_MODEL`，地址和密钥复用主模型配置。请求最多等待 8 秒，并发最多 2 个；相同问题的成功判断缓存 10 分钟，失败时按关键词兜底并显示「规则推荐」。该判断不调用研究工具、不创建研究任务。手动选择后停止自动判断，可一键恢复。

判断期间不能开始研究；确认后的判断编号随自动模式提交，后端据此校验标的数量并生成实际计划。记录过期或服务重启时会要求重新确认；浏览器收到失效提示后重新识别。网络失败时明确提交规则兜底，保持预览与执行路径一致。

工作台在提交前展示「本次研究范围」，使用与后端相同的研究计划生成路径、历史窗口和报告结构；快速筛选固定五年、股东回报固定八年。输入检查可以定位研究问题、标的或补充资料；代码格式校验与后端共用规则，港股补齐代码并合并重复标的，多公司比较按规范化后的不同标的计数。自动识别失败可直接重试，修改问题后旧识别结果不再允许提交。

未加入的资料文字、未保存的编辑和进行中的导入会阻止创建任务；组合约束不完整或未配置网页补充只说明本次研究限制，不阻止可执行的研究。模型服务明确未配置时显示原因并保留可编辑输入。提交结果不确定时提供研究记录入口，并继续使用原提交标识确认同一任务。

执行进度区分排队、分析、计算、补证、复核、保存与待保存，不用阶段数量推算耗时或完成百分比。采集结束与资料完整分别展示。失败恢复说明重试研究将重新采集并替换当前执行内容，重试保存只保存当前服务中的原结果；正式报告在保存确认后提供。

详情页默认以报告正文为主。「研究过程」抽屉保留研究设置、阶段记录和原页复核；网页资料归入证据来源，最终判断依据及待核实事项归入审计记录，不再重复展示网页补证卡片和验证计划卡片。阅读提示保留数量并默认收起；正文开头紧凑展示研究判断及后续研究入口，待核实数量合并到「判断依据与验证条件」展开入口，完整摘要与验证条件可展开阅读。来源和审计统一通过顶部页签访问，不再单设重复入口行。向下滚动后显示「回到顶部」按钮，支持键盘操作和减少动态效果偏好。抽屉支持键盘关闭、返回原入口及跳转证据来源，运行中的草稿同样优先展示。

验证入口：`node --test tests/research-preparation.test.mjs tests/research-progress.test.mjs tests/research-recovery.test.mjs`；界面集成使用本地合成资料，`UI_TEST_FILTER='preparation-|delivery-|detail-direct-retry|quick-screen-progress|web-followup-status'` 选择对应场景。

### 文档处理与模型职责分工

前端上传和后端下载共用文档解析逻辑。MD/TXT、Word（DOCX）和普通 PDF 提取文本；Excel（XLSX）转为单元格 JSON，保留工作表顺序、地址、原始值与公式，未保存的公式结果不当作零；统一交给 deepseek-flash 进行研究、工具调用和最终审计。

扫描 PDF、财务图表和截图先由 deepseek-flash 读取，再把带页码与不确定性的转写交给分析模型。普通文字 PDF 不无条件调用 Vision。每份 PDF 最多补读 2 页，自动获取每任务最多新增读取 6 页；未覆盖范围和失败分别披露。Vision 的读数会与程序文字对照，但不自动成为已核实计算依据。

主模型配置 LLM_MODEL=deepseek-flash；视觉模型配置 LLM_VISION_MODEL=deepseek-flash。Vision 默认复用主模型的地址和密钥，可分别配置 LLM_VISION_BASE_URL、LLM_VISION_API_KEY；LLM_VISION_INPUT=off 可关闭视觉读取。密钥仅保存在后端。

Vision 使用非思考模式读取，分析模型保持默认思考模式负责深度分析。分析模型工具调用所需的模型上下文仅在请求间传递，不输出到报告、执行轨迹或用户界面。

原页视图在 data/visual-attachments 按内容摘要归档。审计由 Vision 按 6 页/12 MB 图片窗口复读，分析模型只接收转写结果，不接收原始图片。缺失、失效、修改过的资料关联和视觉复读失败明确披露。文件中的指令始终作为不可信资料。

填写研究问题，添加最多3个证券代码（A股6位、港股1～5位、美股Ticker）。“查看行情”预览快照；“开始研究”按任务、配置和权限获取行情、结构化财务、官方披露及股东回报等资料，必要时按缺口补充网页正文。任务支持取消、执行轨迹、历史搜索、重载输入和Markdown导出。

| 市场 | 行情 | 官方披露 | 数据商补充（按配置、权限与任务） |
|---|---|---|---|
| A股 | 长桥优先（适配且配置后），东方财富、腾讯备用 | 巨潮定期报告及分红、回购、注销公告原文 | Tushare三张财务表、分红、回购、股本与历史估值 |
| 港股 | 长桥优先（配置后），东方财富、腾讯备用 | 港交所与巨潮独立目录、同报告期替代原件、分派及股本公告 | Tushare三张财务表；长桥基本面的分红、回购、公司行动与历史估值 |
| 美股 | 长桥优先（配置后），Yahoo Finance、腾讯备用 | SEC申报正文、官方XBRL核心事实及选定临时披露的实际链接附件 | Tushare三张财务表；长桥基本面的分红、回购、公司行动与历史估值 |

网页补充在启用并配置搜索后执行：先检索已有资料，再由 Tavily、Brave 定位原始网页，读取正文后纳入证据，搜索摘要不作为研究证据。数据商资料与官方原件分别标注，接入成功不等于每次取得全部资料。工作台、首页、手册及采集阶段的展示文案共用 `shared/research-data-copy.mjs`，具体使用来源和缺口以本次研究记录为准。

行情是**最新可得快照，可能延迟**，不是交易所逐笔直连。行情时间与抓取时间分开记录，休市显示最近交易行情。行情币种与财报币种分别验证，不默认港股财报为HKD。未核实口径的行情PE不自动用于估值。

财报历史范围3/5/8年；初筛按需缩减，其余模式按年度窗口和最近八个报告期选择，股东回报默认八年。年度缺口不再用更老年报填补。港股并用港交所和巨潮目录并保留相同报告期的下载替代；SEC最多补充8个历史目录，并读取正文、近期8-K/6-K及其实际链接的附件。分页、正文与采集预算的缺口分别记录。

PDF单文件32MB、解析180秒、最多600页/150万字符。PDF.js使用随依赖安装的CMap、标准字体和WASM文件，避免部分中文财报漏掉项目名称。先逐页保存原生文字、质量、页码和行列位置，再补做本地OCR，优先处理有财务表标题、乱码或无文字层的正文，封面及末页优先级较低。OCR阶段超时仍保留此前读取的全部原生正文。每份文件最多识别4页、累计90秒，单页最多45秒，每次调用重新计算剩余预算；渲染确认纯空白的页面不占识别页数，未处理页和失败原因单独记录。OCR只有文字、没有有效坐标时仍生成可检索片段，不编造行列位置；较差识别结果保留原始提取内容。中英文字库随固定依赖部署，运行时不从CDN下载，也不发送原件给外部OCR服务。OCR识别置信度不是财务准确率，数字仍待原件核对，不能单独作为计算依据。

已解析原文按证券、URL及解析版本持久归档最长10年，保留抓取时间、原件SHA256、文本及结构化证据完整性校验；读取归档不会重置原抓取时间。解析版本升级会重新读取原件，失败时可回退已校验旧文本并明确标记旧版限制。目录独立刷新以发现新披露与修订。缓存保留提取内容而非原PDF二进制。界面仅预览前12000字符，模型按页和表格检索，命中返回来源ID、块编号、页码、表头上下文及识别限制。

请求遇到连接重置、超时、HTTP 408/500/502/503/504 时进行退避重试，通常最多3次；行情每个来源最多2次、总计最多11秒，失败后切换独立备用源。403不重试并冷却15分钟；429不立即重试，至少冷却60秒并尊重 `Retry-After`。SEC请求统一节流，同属SEC的域名共享限流冷却；不通过切换SEC域名绕过拒绝访问。

行情、目录和SEC数据的相同请求并发复用，单个页面取消不影响其他仍在等待的请求；全部调用者取消时停止共享请求。内存缓存有容量上限：行情15秒、证券目录24小时、SEC公司查询1小时、SEC披露和XBRL响应5分钟、选定财报目录1分钟。行情各来源都失败时，仅允许使用15分钟内成功获取并保存在内存或数据库的快照，并在界面与研究来源中明确标为旧快照，保留原行情时间和抓取时间。财报分页或SEC历史目录失败会保留已找到的可读报告，同时记录缺口；不将缺失事实填为零。

SEC备用公司目录与Submissions接口分别按[SEC访问说明](https://www.sec.gov/search-filings/edgar-search-assistance/accessing-edgar-data)和[官方API说明](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)实现；获取财务数据前再次核对Ticker及CIK。请在 `SEC_USER_AGENT` 填入应用名与真实联系邮箱。

联网诊断：`node --env-file-if-exists=.env scripts/data-diagnostics.mjs`。它检查三市场主/备用行情、巨潮最新PDF正文、SEC官方XBRL与备用公司目录，不调用模型或创建研究任务；成功读取的行情可保存到本地归档。诊断结果只代表当次连接状态。

美股分别读取官方申报正文与XBRL核心财务数据。年度和季度申报覆盖10-K、10-Q、20-F、40-F及修订，另外选取近期8-K/6-K及其结果附件。HTML保留表头、表格行及跨行跨列标记；内嵌XBRL补充CompanyFacts，按原始contextRef/unitRef核对实体CIK、实际起止日、维度、币种、scale和sign，不以财年标签代替实际期间，不重复乘展示倍数。最多读取20000个数值标签；已支持常见小数/千位转换、嵌套数值标签，nil、未知转换、跨文档引用和异常数值不作为有效事实。自定义概念保留原标签且不自动映射到核心指标；分部维度与合并口径分开。同期间修订保留历史，同日冲突不自动选值，不自动拼接TTM。核心字段覆盖检查的“observed”只表示看到标准标签，不是财务审计，缺标签也不代表公司没有披露。来源页提供官方申报原件链接。

来源403/429、接口变化、抓取或解析失败均明确报错，不绕过限制、不编造数据。任一标的完全没有可读官方财报时停止模型研究；部分失败保留缺口。公开接口没有服务可用性保证，长期生产使用应接入授权数据商。

### 可选接入：长桥行情、基本面与 Tushare 财务数据

在本地 `.env` 或部署用 `.env.production` 中补充以下变量。凭证只在服务端读取，不放入 `VITE_` 变量、不发送给模型或前端。未配置时继续使用现有公开来源。

```dotenv
TUSHARE_TOKEN=
LONGBRIDGE_APP_KEY=
LONGBRIDGE_APP_SECRET=
LONGBRIDGE_ACCESS_TOKEN=
```

- 长桥三项齐全后优先提供沪深 A 股、港股、美股行情，北交所继续走现有来源。接入官方 `longbridge` Node SDK 4.5.0，行情使用 `QuoteContext`，港美股基本面使用 `FundamentalContext`，不使用账户或交易接口。行情币种取证券基础信息；保留来源时间，不混入盘前、盘后、夜盘字段。连接在独立子进程中运行，行情10秒、基本面30秒超时；全部等待者取消时释放连接，原生SDK退出不会影响主服务。权限取决于账户实际开通情况。配置参考[官方 SDK](https://github.com/longbridge/openapi/tree/main/nodejs)。
- Tushare Token 配置后，按股票和年份查询三市场的利润表、资产负债表、现金流量表，经 HTTPS JSON 接口获取，结果缓存5分钟。原字段、报告类型、空值及修订记录保留，接口权限失败不阻止其他表与官方采集。港股、美股接口的币种和金额单位未明确返回时保持未知，需从官方原文核对；报告期不标成披露日，不将这些数据当作可直接用于时点回测的数据。来源明确标注“结构化财务（数据商）”，链接指向数据接口说明，不伪装为财报原件，也不计入官方财报成功读取数。参考[Tushare HTTP 接入](https://tushare.pro/document/1?doc_id=130)、[A股财务](https://tushare.pro/document/2?doc_id=33)、[港股财务](https://tushare.pro/document/2?doc_id=389)、[美股财务](https://tushare.pro/document/2?doc_id=394)。

配置后重启服务，再运行下列只读验证。它直接检查长桥与 Tushare，不会以公开备用源的成功代替新数据源验证，也不会调用模型、写研究记录或下单。

```powershell
node --env-file-if-exists=.env scripts/data-provider-diagnostics.mjs
```

检查贵州茅台、腾讯控股、苹果的报价及三张财务表；退出码 `0` 为全部通过，`1` 为至少一项失败，`2` 为凭证未配置而跳过。未配置时只能完成模拟与本地 SDK 加载验证，无法验证账户权限、真实延迟和财务口径。

### 股东回报与数据口径

配置 Tushare 后，A 股额外采集[分红送转](https://tushare.pro/document/2?doc_id=103)、[回购公告进度](https://tushare.pro/document/2?doc_id=124)和[每日股本](https://tushare.pro/document/2?doc_id=32)。这些接口与三张财务表共用请求间隔（600毫秒）、5分钟缓存和权限错误冷却。财务表多取一个年度，用于首年平均权益的期初值；模式 F 检查最近八个完整年度，并保留当年新增记录。

- 分红保留全部状态及日期，分别列出预案、实施记录和已到派息日的记录；检测同一事件的冲突数值。无记录不等于零分红，特别分红仍需官方原文辨别，不直接生成可持续DPS或支付率。
- 回购使用文档支持的日期参数查询全市场，再严格匹配证券。满2000行时拆分日期重取，每标的最多128次、120秒，达到上限保留已取得记录并标注未完成日期段；多次公告的同一原始记录去重，但不合并累计执行金额。回购用途、方案ID及实际注销证明未提供时保持未知，不推断为注销式回购。
- 股本保留每日原始记录及年度末次观测值，万股明确乘10000转为股；展示首次观察到的变动，变动原因保持未知。长桥三市场报价同时带证券基础信息中的总股数、流通股数和港股股数；静态信息没有生效日期时不拿抓取日期替代，也不视为稀释加权平均股本。
- 每个标的生成“数据覆盖与口径检查”，检查财务年度、期初权益、资产负债数值一致性、分红历史及股本来源。`observed`只表示观察到资料，不表示已经与原文核验。检查记录不能单独作为估值证据；数据商财务/股东回报数据参与计算时须同时关联已读取官方披露，跨证券和已知币种冲突会被阻止。
- 港美股已补接长桥 `valuationHistory`、`dividendDetail`、`buyback` 和 `corpAction`。保留实际返回窗口、采样间隔、日期和空值，不能把少量周/月采样说成完整五年每日历史；分红描述也不能直接作为普通现金股息，须辨别特别/实物分派并核对官方原文。

只读八年验证（默认贵州茅台，可传入另一个 A 股代码）：

```powershell
node --env-file-if-exists=.env scripts/shareholder-data-diagnostics.mjs 600519
```

退出码 `0` 表示查询完成且无请求失败或已知截断，不表示所有业务资料完备或财务审计通过；`1` 为请求失败或范围不完整，`2` 为未配置凭证。脚本不调用模型或交易、不写研究任务；成功读取的数据可写入本地归档。

## 数据完整性与连续可用性

- A股 `daily_basic` 读取历史PE/PE-TTM、PB、PS/PS-TTM及股息率，确定性计算三年、五年经验分位；空值、无效比率和历史不足均明示。港美股采用长桥实际返回的估值采样点，保留缺少指标和历史长度，不混用采样频率。
- 官方原件读取使用严格域名与路径允许列表。港股下载失败可尝试同公司、同报告期的已发现替代原件；财报和目录在MongoDB归档，读取时校验文本哈希。归档失效或写入失败不阻断本次正常外部读取，但会报告缓存故障。
- 官方目录刷新失败可回用30天内目录，明确标为旧目录；行情回用上限15分钟；Tushare/长桥基本面故障可回用30天内记录，估值数据回用上限2天。权限拒绝不伪装为成功；来源时间与抓取时间不重新标新。凭据仅参与不可逆账户范围键，不写入资料正文。
- 股东回报补充巨潮分红/实施/回购/注销公告、港交所分派与证券月报（按历史窗口）和最近90天翌日披露；按年度与实施相关标题选择最多24份专项原件。SEC临时披露选最近8份，各最多3份已链接的结果附件。达到预算如实保留未读范围。
- 分红实施记录按事件日期去重，冲突不猜测；回购原文线索按来源ID与页码定位，关键词命中不证明实际注销。XBRL保留真实起止日、单位和修订，不重复乘千/百万、不混加单季与累计。
- 外部数据商或官方站点均不能保证绝对无故障。本实现提高故障时的连续可用性，并在无有效来源时保留缺失；它不提供100%可用性的合同SLA，也不将过期或未核验数据用于宣称当前精确估值。

完整采集验收（不运行模型或交易，会保存本地数据归档）：

```powershell
node --env-file-if-exists=.env scripts/data-readiness-diagnostics.mjs
```

结果保存为 `artifacts/data-readiness.json`。三个示例的实测通过不代表全市场、全部特殊行业、公司行动或口径均已完备。

随后运行 `node --env-file-if-exists=.env scripts/data-failover-diagnostics.mjs` 可检查数据库归档在新客户端实例中的恢复：注入连接故障，不中断真实服务；验证旧资料保留时间、故障标签及行情15分钟有效上限。它会刷新一次真实行情，读取上一步产生的基本面和官方资料归档，不调用模型或交易。

## 主动网页补充

核心行情、结构化财务和官方报告仍走固定采集接口。研究模型可按具体缺口补充行业统计、公司材料、政策与最新事件原文，后端执行以下顺序：

1. `search_evidence` 检索本次资料库，返回检索编号和真实命中段落。零命中返回空结果，不再用无关段落填充。
2. `search_web` 必须引用该次检索编号并说明尚缺什么。后端重新检查已有资料，再复用同一公开关键词搜索；资料库更新时先要求重新审阅。搜索服务只提供候选链接和定位标题，摘要、自动生成答案和搜索服务给出的日期不会进入证据正文。
3. 直接读取候选原页或PDF，提取正文、原文发布日期、资料期间线索、发布域名、抓取时间和哈希。日期不明或多期间无法对应时保留未知/待核对，不以抓取日期代替。只有成功读取的正文分配新的来源编号。
4. 模型按来源编号检索补充正文；`resolve_web_gap` 要求给出真实连续摘录及其对应理由。程序验证摘录存在，语义判断仍由模型负责。身份、日期、截断和旧资料的限制不会因找到一句话而消失；尚未解决的缺口必须进入最终审计的缺失清单，数据等级标为受限。

本地 `.env` 或部署 `.env.production` 配置如下。Tavily 优先，Brave 为可选独立备用，不需要两家都配置：

```dotenv
WEB_SEARCH_ENABLED=true
TAVILY_API_KEY=
BRAVE_SEARCH_API_KEY=
WEB_RESEARCH_ISSUER_DOMAINS={}
```

密钥仅在后端读取；搜索请求只发送模型提出的公开关键词，不自动发送整个问题、持仓或先前研究。关键词检查拒绝链接、邮箱和本地密钥，模型规则进一步禁止外发私人上下文。搜索语义由模型决定，关键词过滤不等于所有个人信息已被自动识别。未配置或关闭搜索时，固定接口继续工作，网页缺口保持未解决。

`WEB_RESEARCH_ISSUER_DOMAINS` 是操作人员确认的证券与公司官网域名映射，例如 `{"US:AAPL":["apple.com"],"HK:00700":["tencent.com"]}`。内置识别部分监管、统计和交易所域名；搜索排名和模型声称不能自动赋予其他网站“官方”身份。未确认发布者的已读网页可作为待核查补充资料；计算工具拒绝未读正文、身份未知、发布日期未知及搜索摘要，并要求补充财务数字同时关联固定采集得到的官方披露。

每项研究最多6次搜索、8次正文读取，每个缺口最多尝试3个候选，累计联网时间180秒；启用搜索时最多18轮模型工具交互。网页单文件最多12MB，HTML/纯文本最多50万字符，PDF沿用上述解析及本地OCR预算。不执行网页脚本，不越过登录、验证码、403和限流。仅连接通过DNS校验的公开HTTPS地址，并在每次重定向后重新校验及固定解析地址；SEC正文沿用固定采集器的访问限制。若桌面网络返回198.18/15保留地址，会向Cloudflare公共DNS核对该公开域名，再连接校验后的公网地址；可用 `WEB_RESEARCH_PUBLIC_DNS=false` 关闭该兼容处理，不会直接放行保留地址。

已读网页文本和对应链接目录归档30天；正文6小时内可直接复用，超过后尝试刷新，刷新失败明确标记旧资料并保留原时间。搜索失败可复用同一公开查询下的已读原文链接，但继续保留“未确认新披露”的缺口。缓存存文本与哈希，不是原PDF二进制备份。来源界面展示“网页原文（补充）”、原文日期、期间与限制。归档不保证长期站点可用，也不证明网页中的事实正确。

配置后重启服务，执行 `node --env-file-if-exists=.env scripts/web-research-diagnostics.mjs` 验证搜索、原始正文及归档恢复。脚本不调用模型或交易，会写入公开资料归档；未配置凭证时仅测试已知原始链接，退出码2，不能当作真实搜索验收。结果在 `artifacts/web-research-diagnostics.json`。参考 [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)、[Brave Web Search](https://api-dashboard.search.brave.com/api-reference/web/search/get)。

## MongoDB 持久化

`compose.yaml` 部署官方 `mongo:8.0`，仅映射 `127.0.0.1:27017`，使用 Docker 命名卷 `zhiheng-agent_mongodb_data` 和 `zhiheng-agent_mongodb_config`，自动重启策略为 `unless-stopped`。本地开发不设数据库认证，请勿将端口暴露到公网。

默认连接 `mongodb://127.0.0.1:27017`，数据库 `zhiheng_agent`；可通过 `.env` 中的 `MONGODB_URI`、`MONGODB_DATABASE` 修改。数据库不可用时后端启动失败，不回退到文件存储。`GET /api/health` 检查实时数据库连接。

后端每次启动会导入 `data/*.json` 研究任务和 `data/cache/*.json` 未过期缓存。已有任务不会覆盖，旧文件不会删除；损坏文件会明确报错并阻止启动，修复后可重试。也可独立执行 `pnpm db:migrate`。请只运行一个后端实例；重启时将遗留的排队/运行任务标记为中断失败。

任务摘要保存在 `jobs`，完整任务保存在 `job_payloads.files/chunks`，支持超过16MB的研究资料；历史内容版本保留以保障并发读取。财报正文保存在 `report_cache`，读取立即过滤过期数据，TTL 索引异步清理。只有正在运行或保存失败的任务保留在内存供界面查看。

`pnpm db:stop` 停止数据库，`pnpm db:up` 恢复。普通容器重建保留数据；不要执行 `docker compose down -v`，该命令会删除持久化卷。备份可使用容器中的 `mongodump`，恢复使用 `mongorestore`。

`pnpm test:mongodb` 在随机命名的临时数据库验证大文本、重连持久化、任务恢复、缓存过期和幂等迁移，结束后清理测试数据库。实现参考 [MongoDB GridFS 文档](https://www.mongodb.com/docs/drivers/node/current/crud/gridfs/) 和 [MongoDB 官方镜像](https://hub.docker.com/_/mongo)。

业务适配和大部分研究审计仍由模型执行。数值工具不认证事实，官方采集不代表全部假设已核实。跨币种、正常化、历史覆盖与估值模型适配仍需复核；没有完整组合上下文不得输出具体权重。

`pnpm test` 覆盖公式、输入、行情精度、来源安全、XBRL期间和模拟工具闭环。测试常量只存在于测试文件，不进入应用。


ode scripts/data-smoke.mjs` 做真实三市场抓取测试，将元数据写入 `artifacts/data-smoke.json`，不调用模型、不建立研究任务。`scripts/smoke.mjs` 是可选Playwright真实行情界面测试，设置 `PLAYWRIGHT_MODULE` 为已安装Playwright入口。

依据：[巨潮资讯](https://www.cninfo.com.cn/new/index)、[SEC官方API](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)、[PDF.js](https://mozilla.github.io/pdf.js/examples/)、[OpenAI接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。
`LLM_TIMEOUT_MS` 控制模型连接连续无内容或保活信号的等待时限，默认300000毫秒、允许30000～600000毫秒。流式返回正文、推理内容、工具参数或标准 `: keep-alive` 心跳时重新计时。心跳只说明连接活跃，不表示已完成研究；等待时会在执行轨迹提示。其他空帧或注释不延长等待，推理内容仍仅保存在私有模型上下文中。`LLM_MAX_DURATION_MS` 控制单次请求总时限，默认1800000毫秒、允许30000～3600000毫秒，持续输出也不能超过该上限。用户取消和阶段自身的较短时限始终有效。审计使用独立精简上下文；未审计草稿不会作为最终报告展示。

`LLM_REVIEW_FORMAT` 默认为 `auto`：审计优先使用严格 JSON Schema，约束当前模式的章节编号、研究动作、置信度、日期格式与字段类型。只有模型接口明确返回不支持该格式的 HTTP 400/422 错误时，才依次兼容 `json_object` 和文本模式；授权、额度、网络或 Schema 本身错误不触发降级。可显式设置 `json_schema`、`json_object` 或 `text`，显式设置不自动降级。格式约束仅用于独立审计，草稿与计算工具接口保持不变。接口格式参考 [OpenAI 结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs)。结构化输出不能替代后续证据及业务校验。

## 实时研究报告

`GET /api/jobs/:id/stream` 使用 SSE 推送当前快照、执行事件和报告增量，断线后浏览器自动重连并重新读取当前快照。离开页面不会取消任务。模型请求启用 `stream: true`，兼容工具参数分片；如果供应商仍返回完整 JSON，也可读取，但无法提供逐字输出。

生成中的内容仅作为未审计预览，审计通过后替换为正式报告；失败或取消时移除预览，导出仅对正式结果开放。执行轨迹按最新在前展示。反向代理需关闭 SSE 缓冲并允许长连接（例如 Nginx `proxy_buffering off; proxy_read_timeout 3600s;`）；服务发送15秒心跳。

草稿阶段只要求可阅读的 Markdown，JSON 交付协议仅用于独立审计阶段。前后端共用预览格式处理：去除包裹整篇报告的 Markdown 代码围栏，完整结构化草稿只提取报告章节，未完成或无法识别的结构化内容显示整理进度，不直接展示内部字段。前端同时兼容旧任务快照中的原始草稿。该处理只影响预览，原始草稿仍提交审计，正式报告仍须通过原有交付校验。

当前单实例以内存广播实时消息、MongoDB持久化任务和财报缓存，无需 Redis。若后续引入多个后端实例、独立任务进程或可靠任务队列，再设计共享任务状态和消息分发；普通 Redis Pub/Sub 不持久化断线消息，可靠重放可评估 Redis Streams。

## 页面路由与研究框架

平台使用 React Router 的浏览器路由：`/` 为首页，`/workbench` 为工作台，`/history` 为研究记录，`/handbook` 为研究手册，`/research/:jobId` 为研究详情；旧地址 `/framework` 保留查询参数与锚点并跳转首页。详情标签页使用 `?tab=audit` 或 `?tab=sources`；记录的关键词、状态、排序、页码保存在查询参数中。部署服务器需将非 API 的页面地址回退到 `dist/index.html`，本项目 Node 服务已支持。

资料解析版本 `evidence-9` 采用先原生提取、后按优先级补识别的流程，补识别结果按原页码替换，保留稳定片段编号。目录点线和特殊勾选符号与乱码分开：保留原文，勾选状态另行标记核对，避免无效 OCR 消耗预算。正文块分别记录质量，整份文件存在未读页或 OCR 页面不再自动排除其中完整、可核对的原生正文。新版本重新解析原件；原件暂不可读时可回退已校验旧版归档并明确标记限制，不改写历史报告。使用 `node scripts/pdf-ocr-diagnostics.mjs <本地PDF路径> <页码>` 可将已有原件的一页转成扫描测试页，检查正文保留、空白页预算和OCR检索，结果写入 `artifacts/pdf-ocr/`，不修改原件或研究记录。

纯数字扫描续页在原生提取为空、失败或文字稀少时保留足量的数字 OCR 结果，仍标为待核对，不覆盖已有原生数字表格，也不能直接作为计算证据。已完成的纯数字 OCR 不因待核对标记反复解析；失败、未处理和补识别超时仍触发缺口刷新。运行 `node scripts/ocr-numeric-diagnostics.mjs` 可用真实本地 OCR 引擎识别合成数字图片，验证正文保留、检索和计算限制，结果写入 `artifacts/ocr-numeric/`。计算失败后的定位建议会再次核验当前资料及片段，排除已变化、缺失、重复或质量已改变的旧检索结果；网页缓存的未来或无效时间戳不能冒充六小时内的新资料。

达到字符上限时保留末行的可读部分，并将对应片段标为截断、待核对，禁止作为完整计算证据。受损字符即使占比很低也会使所在证据片段进入待核对状态，避免长段正常文字掩盖损坏数字。后续页面返回格式异常时不接纳错误页码或证据块，保留此前已读正文和失败说明。从标准输入或命令行求值环境调用解析器时，子线程不继承仅适用于标准输入的参数。

存在未读页、OCR失败、未处理页或补识别超时的官方财报归档，六小时后再次使用时会尝试刷新；普通的“已完成OCR、待原件核对”标记不触发重复解析。刷新主链接失败时继续尝试已知的官方备用原件，再回退旧归档；失败回退保留原抓取时间与缺口。OCR数值比对保留括号负数、整数、百分数、不同小数精度及出现顺序，金额列互换也会标记分歧。整页OCR文字与词块互有缺失时保留两份文字并提示差异，不静默丢掉没有坐标的金额。

扫描表格先识别原图；检测到成组相交的长表格线后，在独立图片副本上清除表格线并用表格分段方式补识别，短负号、小数点及原件不改动。两次识别共用单页和整份文件的时间预算。仅在文字覆盖、置信度及完整金额数量未明显退步时采用表格结果；这些检查不等于财务准确性验证。原图与表格结果有数值分歧时，归档保留两者并生成可检索的备选 OCR 片段（`p页码-ocr-original-b编号` 或 `p页码-ocr-table-b编号`），全部标记待核对。补识别失败或超时保留已经完成的原图结果。部分坐标缺失时回退完整 OCR 文本，避免丢掉金额或符号，不编造位置。图片尺寸在取整后仍受600万像素限制，微弱像素不当作纯空白。

检索和计算共用证据编号解析，兼容原生页块、行情片段、数据商行记录及 XBRL 事实。真实来源、官方佐证、币种、股类和 OCR 限制仍须校验。引用失败时返回本次已检索的可用片段帮助定位，不替模型编造参数来源。财务运算支持第一季度累计口径；半年累计仍不能冒充单季。报告中的逐页解析提示可展开查看，其他使用限制保持可见。可用 `node --env-file-if-exists=.env scripts/material-processing-diagnostics.mjs <研究ID...>` 只读回放历史失败调用，不调用模型、不改写研究记录；回放成功只表示引用及运算检查通过。

核对特定PDF页时，可在 `search_evidence` 中配合 `sourceId` 使用 `query: "第34页"`、`"page 34"` 或 `"第34页 现金流"`，按实际PDF页码筛选；不存在的页不回退其他页。已经声明解析结构但正文块为空的资料保留缺口，不从残留文本重新生成旧式证据块；旧式无结构资料仍可检索，XBRL事实独立保留。重复资料编号或片段编号在检索中标明歧义，计算不能默认采用第一条。已核实发布者的网页PDF也不能使用损坏或待核对的文字块计算。

首页集中展示上手指引、研究场景、服务方案、研究流程与原则摘要；六维评分和判断边界移至研究手册，避免首页重复展示详细标准。侧栏直接列出首页、研究工作台、研究记录与研究手册。研究手册的研究纪律页包含阅读标准、`knowledge/modules/rules/17-prohibitions.md`的30条禁止事项与 `knowledge/modules/rules/18-principles.md` 的最终原则；`/handbook?tab=glossary` 的13个术语默认收起，点击名称或使用键盘展开定义、通俗解释、示例与适用边界，可同时展开多项对照。公式计算及高股息说明归入对应条目。手册章节保存在地址中，支持直接访问、刷新和浏览器返回；术语分类手动切换，窄屏完整展示三个分类。原文变更时，同步维护 `src/config/research-reference.js` 与相关展示文案。

失败或已取消的研究可在详情页直接“重试研究”。`POST /api/jobs/:id/retry` 接收 `expectedRetryCount`（首次为0），从服务端保存的输入重新执行当前记录，保持研究ID、创建时间和详情地址不变，不增加研究记录。原问题、已确定的模式、深度、标的、年份、组合信息及已保存的历史对照快照沿用；旧错误、结果、行情、来源、草稿和阶段状态重置为本轮内容，并记录重试次数与最近重试时间。前端保持当前标签页并重新连接进度；桌面和移动端共用提交锁。服务端通过运行锁、容量预留和数据库条件更新防止并发重启、过期请求与已删除记录被恢复。写入失败时保留原状态，允许再次尝试。提交期间离开页面不会被强制跳回。已完成报告的“复用研究输入”仍只载入工作台，不自动提交。

研究框架页围绕公司质量、证据链、估值假设和证伪跟踪说明价值；六类场景可切换查看交付内容并进入工作台，五个流程步骤支持点击与键盘切换。两组标签默认从各自第一个标签开始，每4秒自动轮播，不显示独立控制按钮；悬停、聚焦内容、离开可见区域或切到后台时暂停，恢复后重新计时。遵循系统“减少动态效果”偏好，启用该偏好时仅手动切换标签。两组内容在切换时保持高度稳定，窄屏只横向移动标签栏以显示当前标签。评分区域只展示规则权重，不预置公司分数。页面与新增交互复用 shadcn/ui，支持320px手机及桌面。各页面底部重复的品牌文案已移除。

`knowledge/ENTRY.md` 是唯一执行入口，`knowledge/modules.json` 是唯一目录，业务原文只维护于 `knowledge/modules/rules/`，详见 [V4.7 加载说明](knowledge/README.md)。`shared/research-framework.mjs` 是其可执行映射，统一六类任务、必要辅助模块、五个阶段、六维评分和输出协议。`server/knowledge.mjs` 在启动时检查目录版本与绑定章节，按任务及规则查询读取独立文件；原文版本、日期与SHA256随计划和最终报告保存。规则检索返回完整小节、来源与行号，超出窗口会标记截断。修改Skill时需同步映射与验证，不能只修改宣传页面。

`POST /api/research/plan` 与任务创建共用输入校验、模式路由和历史对照检查，不调用模型。创建时重新生成并保存计划；A 快速筛选强制Quick及五年范围，F 股东回报使用八年检索范围；长期价值研究中的分红问题保留B主模式并增加必要辅助模块。实际读取范围仍受来源覆盖限制，当前不自动展开指数成分或批量筛选全市场。

MODE A 交付协议为版本3：报告分为商业模式、五年趋势、最新一期与单季变化、资产负债表、财务红旗与反证、现金流与资本开支、估值与方法适用性、三个优势、三个风险、下一步验证十个章节。资料不足也须保留该章节及缺口。默认选择五个年度的官方年报和三个近期报告期；不为快筛额外拉取多年股东回报、估值分位或公司行动历史。核心行情及财报继续通过固定接口，网页仅按已有资料的缺口补充。

`calculate_screen_metrics` 校验显式金额单位、行业、ROE定义、实际起止期间和逐行来源编号，运算覆盖增长、Quick FCF、累计流量推导单季、历史ROE均值/中位数/总体标准差及余额比较。缺失不补零，基数非正不算增长率，重复或重叠年度先处理修订，直接单季与推导单季冲突保留。银行、保险等金融企业不计算工业企业现金流代理。工具不独立核实输入事实；历史ROE统计不等于正常化ROE。MODE A 在工具定义和执行入口均禁止完整DCF及股息估值工具。

首页六类场景保持简要介绍：核心用途、交付重点和简短章节清单直接铺开，桌面双列、手机单列，不使用展开/折叠。展示文案在 `src/config/research-presentation.js`，首页只读取交付章节，不生成或展示内部执行计划。

工作台保留问题、标的、研究路径、报告深度、历史范围与补充背景，移除范围卡片和计划预览，也不再发起计划预览请求。详情保留研究报告、审计记录、证据来源三个标签，移除研究范围入口和研究思路页；旧 `?tab=approach` 链接自动回到报告。执行轨迹不展示内部计划及规则读取数据。前台导出仅包含正式报告、审计与来源；内部计划、规则版本和计算过程仍保存在后台记录中，后台研究与审计协议继续执行。

工作台对 MODE A 隐藏深度/年限选择框；问题自动匹配快筛时也使用同一交互。按钮为“开始快速筛选”，请求按 Quick 与五年范围提交。用户可以填写筛选关注点，切换研究路径时保留已有输入。详情页区分读取资料、查证、计算、复核与未完成状态，并解释“报告已完成”及尚待核实事项。结论为“深度研究”的快筛可通过“准备深度研究”将同一标的与主要待验证事项带入新的工作台输入；此操作不创建任务，提交后才运行。财报更新入口继续用于对照旧判断。

计划与创建API均新增可选字段：`previousResearch`（上次结论，最多30000字）、`baselineJobId`（已完成的同标的研究）、`portfolioContext`（`holdings`、`weights`、`assetRange`、`riskTolerance`、`industryExposure`、`liquidityNeeds`，每项最多4000字）。普通研究背景继续使用`portfolio`。六项字段齐备只是结构完整，还需要模型核实有效性；背景描述不自动授予具体仓位结论。

财报更新可从详情页发起，或在工作台选择旧报告。服务端检查旧报告完成状态与标的覆盖，保存最多60000字符的报告快照及结构化结论，并将旧引用标成历史来源。旧报告后续删除不影响已经创建的更新任务。未提供对照时只建立本期基线，不生成无依据的升级、降级或剔除判断。

估值工具要求记录币种、期间、股本口径、假设与有效来源编号，披露目录不能充作计算证据。模型须匹配行业、正常化假设和现金流口径；工具验证数值和声明结构，不独立认证参数事实。

审计按主模式返回`sections`、`audit`和`decision`。程序检查必需章节、研究动作、五级置信度、至少三条不同的证伪条件、日期、数据/质量/估值/风险复核项、组合边界及正文来源编号。Deep评分只能使用25/15/25/20/5/10体系，缺失值保留null，正文评分由校验后的字段生成；同类倍数变式不能充作多个独立估值方法。

格式解析和内容校验分别处理：完整 JSON 外的代码围栏、字符串内未转义的换行/制表符、结尾多余逗号可作无歧义规范化，并在轨迹中记录；不补括号、字段、日期、来源或财务数字，不接受截断对象。JSON 格式、输出截断或流中断最多修复两次；内容校验一次列出独立字段与引用问题，最多修正两次，相同问题修正后仍存在则提前停止，格式与内容纠错合计最多五轮生成；独立补证流程的调用预算另计。格式重试不会从头重跑研究；取消、权限错误和模型拒绝不走格式重试。资料缺口可在初审尚未通过时进入补证，最终仍须通过全部交付检查。资料不足且已披露影响、收敛判断时用limited；failed须先修正实质问题，不能仅改状态。无法修复时不发布正式报告，执行轨迹显示具体问题与停止原因。这些是结构和边界校验，不代替事实核验，也不能保证模型对自然语言规则的遵循。

新报告的详情页展示研究动作、置信度、证伪条件和信息缺口；摘要中的`researchOutcome`供研究记录和最近研究展示。旧报告保持原有阅读、导出和输入复用能力，不补造结构化结论。

研究引擎记录明确问题、采集证据、分析查证、工具计算、复核交付五个阶段，并通过 SSE 的 `workflow` 事件更新详情。估值按需调用，未使用时明确标记；工具事件携带 `toolCallId` 与 `toolName` 关联输入和结果。最终报告额外保存结构化程序校验记录。计划与阶段随任务保存至 MongoDB；旧记录保持可读，不补造执行阶段。服务重启时未完成任务仍标记为中断失败。

工作台支持步骤定位、研究路径切换和 `Ctrl / ⌘ + Enter` 提交；选择股东回报模式时显示固定八年范围。研究记录可按问题、模式和证券信息搜索，高亮命中文字，状态筛选数量随搜索更新；按 Escape 清空关键词。列表支持排序、分页与手动刷新，有进行中的任务时每15秒更新。最近研究使用整项链接，突出当前记录并保留新标签页打开方式。详情的状态紧跟标题，桌面操作与标题同处一行并靠右对齐，整体吸顶；长标题省略显示，可悬停查看完整标题；报告、审计、来源三个标签页保持相同的正文宽度，右侧保留执行轨迹。页签旁常驻报告目录入口，随页签一起吸顶；桌面使用浮层，手机和平板使用抽屉。在审计或来源页选择章节，会自动切回报告并定位到工具栏下方；没有章节时入口禁用。手机和平板的研究操作仍由标题下方入口打开，执行轨迹显示在正文下方。详情支持来源搜索与批量展开、执行事件筛选、已结束任务的输入复用；阅读模式仍可取消任务。按钮、卡片、标签、下拉选择和折叠区域复用现有 shadcn/ui 组件。

界面回归检查：先启动前端，再运行 `pnpm test:ui`。默认访问 `http://127.0.0.1:5173`，可用 `UI_BASE_URL` 指定其他本机端口。需要已安装的 Playwright 与 Edge；`PLAYWRIGHT_MODULE` 可指定 Playwright 模块入口。测试拦截 API 并使用内存模拟数据，不调用真实模型或修改实际研究记录；结果与截图写入 `artifacts/ui-*`。


### MODE B 深度研究交付

工作台的「比亚迪深度投资研究」示例仅填写问题，并选择 MODE B、完整展开和五年历史；核对标的后点击「开始深度研究」才创建任务。规则更新须通过完整校验；同一框架版本内，新任务自动绑定最新有效快照，正文模块按任务加载并保存实际读取记录；不需要将它们作为财报上传。

新任务使用交付协议版本4，MODE B 增加核心矛盾、估值模型分歧、后续验证章节，以及关联本次来源的3至8项公开证据判断。详情页在审计记录中查看判断依据，在研究过程中查看实际阶段进展；深度研究导出包含验证计划与摘要、实际工具记录、完整报告、审计和来源。旧任务没有保存的摘要不补造；MODE A维持既有阅读与导出方式。

新增 `calculate_normalized_earnings`，在行业适配且口径明确时，以普通股权益、对应股本、正常化ROE和PE区间计算盈利、EPS、价值及同币种安全边际，每情景分别调用并保存来源口径。历史ROE统计不自动成为正常化假设；缺少汇率不能跨币种比价，维护性与成长性Capex无法可靠拆分时不强算DCF。参考案例仅用于优化验证流程，不预置数值、结论或工具调用。


### 交付前强制补证

主研究生成草稿后，先做初步审计；程序逐项检查审计列出的缺口。对可公开核实的财务、行情、汇率、业务及行业等缺口，以已确认的证券和固定公开主题构造检索词，先定向检索现有资料并核对原文；仍不足时由程序调用网页搜索、读取正文、重新检索并验证连续摘录。持仓约束、模型经验参数等不发送到搜索服务，保留需要用户信息或人工核对的原因。

每次最多处理6项可检索缺口，并与研究前段共享6次搜索、8份正文、180秒网络预算；新增来源后可追加最多4轮工具调用进行必要计算，然后重新审计。未解决的F编号缺口不能在最终报告中消失，最终复核新出现的缺口保留轮次上限说明；关键数据受限时必须降低置信度。日期未知、来源身份或解析有问题的网页不能被包装成已核实证据。

同一任务、同一标的、同一公开检索词已有成功读取的原文时，后续检索编号可复用该次资料，不再次消耗联网和正文读取额度；搜索或读取失败且没有可用正文时仍可按剩余预算重试。不同标的或检索词不共享这项复用。每个新缺口仍独立编号并等待核对，不继承此前缺口的解决结论，旧目录、发布日期和解析限制保留。候选链接先规范化、去重，再选最多3份不同原件，重复链接不占读取名额。任务及轨迹记录复用次数、重复链接数和原检索编号；页面同时统计主研究网页缺口与交付前补证缺口，已关联同一G编号的F项不重复累加。复用和关键词命中均不代表问题已解决。

补证状态保存于任务及结果的 `evidenceFollowup`，工具输入、返回、停止原因记录在轨迹中；实时详情显示网页搜索次数、新增已读资料数及剩余限制，完整导出保留补证记录。该检查只补查已报告的缺口，不保证所有隐含问题都被发现，也不要求每项研究必须联网。此前完成的报告不会自动重跑。

### 资料处理与复核窗口

主财报正文默认最多两份同时下载和解析，同一证券的相同原件链接去重；处理完成后按目录顺序分配来源编号，单份失败不会丢弃其他原件。取消后停止调度新文件并等待已启动读取退出。沿用原件归档校验和解析版本规则，保留缓存、过期、缺页及OCR限制；读取进度区分成功与失败，覆盖记录保存处理耗时、去重数和归档复用数。

初次审计不再直接截取JSON字符串。工具记录优先保留近期成功计算的实际输入、返回及依据，仍保留其他情景和失败记录；证据优先纳入这些计算指定的原文块，再按来源轮流纳入相关资料及草稿引用，两个窗口分别最多40000字符。超大或超出窗口的记录整体省略并登记编号，不切断表格或补造缺失数据。`calculationEvidence`区分指定片段尚未检索与超出本轮容量，同来源的其他片段不能替代。执行轨迹保存`audit_context`，结果的`validation.initialEvidenceWindow`保存初次范围，`validation.evidenceWindows`分轮保留初次及补证复核资料包；后续直接调用工具的返回仍见执行记录。这不代表全部原件已核实；详情与两种导出均显示分轮范围、引用缺口和计算依据限制，不将重复片段累加为新增证据，兼容只有初次范围的旧记录。来源导出保留内容指纹、读取页数和解析版本。

### 财报更新（MODE C）

财报更新以最新正式披露和旧判断对照为主，按六部分交付：最新财报与对照范围、累计与单季财务变化、关键变量与反证、旧判断与本期证据、估值参数与区间影响、研究动作与下期验证。专项规则随任务按需加载，本次规则指纹继续随研究保存；外部参考案例仅用于提出待验证问题，不能复制其数字、结论或工具记录当作新事实。交付协议第5版要求MODE C保存3至8项公开证据判断摘要；旧版交付仍按保存的协议校验。

未提供旧研究时动作限定“建立基线”，允许比较已读历史财报期间，但不声称旧投资逻辑增强或削弱。有旧结论时仍用升级、维持、降级、剔除；偏积极等表述放在理由里。工作台提供比亚迪最新财报示例、同标的对照筛选、旧参数与关注变量输入及专用开始按钮；详情展示对照范围、更新计划、实际执行阶段和复核后摘要，计算缺口仍单独可见。

`calculate_screen_metrics`可用于MODE C：新增扣非归母利润、毛利、营业成本、海外收入，核算累计同比、单季同比/环比、利润率与百分点变化、Quick FCF变化。仅同口径累计流量相减拆季，利润率重新计算，不相减ROE或EPS；单季重复或冲突时不作该季比较。存货/应收周转使用匹配期间首尾余额的简单平均、营业成本/收入和实际期间天数，缺少期初余额、分母或金融行业不适用时返回null并说明。计算验证运算与结构，不证明输入财务数字正确，也不把单季改善直接映射为正常化ROE或目标价上调。

验证：`node --test tests/earnings-update.test.mjs`覆盖新旧基线动作、拆季与比率、冲突/缺失输入、周转口径及MODE C真实工具执行路径（模型响应为合成夹具）。`UI_TEST_FILTER='earnings-update|framework-context'`运行对应界面集成用例，验证320/1440像素工作台、详情及从旧研究发起更新；所有测试使用本地合成数据，不创建真实研究。

### 多公司比较（MODE D）

交付协议第6版为MODE D增加共同口径、业务成长、财务现金流、ROE与资本回报、股东回报、估值适配、逐家公司动作七部分，以及3至8项公开证据判断摘要。专项规则由后端按需加载，参考案例只指导待验证问题，不预置比亚迪、长城汽车或赛力斯的数字、评分、排名。质量、当前价格吸引力和研究优先级分别判断，不强制选出综合冠军。

`calculate_comparison`独立校验2至3家公司的来源和财务运算，再检查共同期间、业务适配组、币种、单位、行情时点及ROE历史窗口；必须覆盖本次全部证券，禁止跨公司串用来源。缺失值保留null，亏损和负现金流保留原值，历史窗口不一致不比较稳定性。复杂估值继续逐家公司核算；可比性检查仅验证输入结构与运算，不证明财务数字或业务分组正确。

工作台使用“多公司比较”路径、专用示例与开始按钮，至少选择两个不同标的，支持比较重点输入。详情展示专用执行阶段、公开比较计划、最近一次可比口径检查，以及每家公司的动作、置信度、证据、缺口和验证条件；导出正文也包含逐家公司判断。交付检查拒绝遗漏公司、重复公司、串用来源或缺少验证条件，旧版记录保持可读，不补造卡片。

验证：`node --test tests/company-comparison.test.mjs`覆盖路由、输入、可比边界、来源隔离、结构化交付及MODE D工具执行；`UI_TEST_FILTER='company-comparison'`覆盖320/1440像素的工作台和详情。测试只使用合成资料与模型响应，不创建真实研究任务。

### 补充资料与保存

工作台“补充资料”支持批量选择、拖拽文件和粘贴截图。所有原文件直接以二进制发送到 `/api/materials/read`，前端仅检查格式、文件大小，展示进度和后端返回正文；不再查询能力后决定是否上传，也不在浏览器中提取 PDF/Office/文本或运行 OCR。浏览器构建不再包含 OCR 语言资源和解析工作线程。

后端统一处理文档：MD/TXT、Word、普通 PDF 提取文字，Excel 转为保留工作表、单元格地址、公式和原始值的 JSON；扫描页、图表及截图由 Vision 读取，再交给分析模型 分析与审计。PDF 原页读取失败时可由后端程序提取或 OCR，并明确保留未覆盖范围；前端不进行识别回退。每份文件最多 10 MiB，PDF 最多 100 页，最多 6 份资料，每份正文 2 万字、合计 6 万字；超限报错，不静默截断。Office 展开限制 24 MiB、1200 个 XML/关系文件，不跟随外部关系；内嵌图片可单独导入。

导入串行处理，单份上传与处理等待最多 150 秒，后端处理预算 110 秒。失败不占资料名额，不影响后续文件；当前页面保留失败的 File 对象、显示错误原因，支持重试未完成项。取消或超时不接受迟到结果；刷新或离开后，尚未成功处理的原文件需重新选择。原件的临时预览只在当前页面可用；归档成功的原页通过关联编号提供给研究复核，草稿不保存图片二进制。仅改资料名称保留原页关联，改正文后清除关联，作为用户核对笔记使用。

资料支持正文查找、复制、编辑及撤销移除；未加入的文字和编辑草稿随当前标签页暂存。文件处理完成、文字加入或清空、修改保存或取消后才可提交研究。API 使用 `referenceMaterials`，旧 `sources` 输入仅作兼容接收，不接受用户提供的官方认证或解析标记。M 编号资料是研究线索，不能替代 S 编号原始证据或直接用于财务计算。文件内指令按不可信材料处理，专项规则由后端独立加载，上传同名文件不替换平台规则。

补证后的审计也使用完整证据与工具记录窗口，补证返回的原文纳入后续计算恢复的可检索依据。运行期间在阶段变化、工具返回和复核节点请求保存，普通快照至少间隔15秒，每次运行最多20次，避免高频复制完整任务。保存串行执行；结束时先停止并等待阶段保存，再写最终结果。中途保存失败会保留提示并允许后续节点重试；服务重启后仍标记中断，保留最近成功保存的内容，不自动冒充断点续跑或完成报告。

工作台输入会在当前标签页的`sessionStorage`中暂存，最多恢复24小时内的草稿，包含手动标的、组合背景、已加入材料和仍在编辑的材料文字；不保存运行结果或来源认证标记。刷新不会自动提交任务，自动识别的标的会重新解析，手动及用户已选择的标的以手动状态恢复。提交成功、新建研究或点击“清空输入”会清除对应草稿；浏览器禁止存储或空间不足时显示提示，不阻止研究提交。

详情页仍以实时事件为主，事件静默超过15秒时补取状态，页面回到前台及连接恢复时也按节流规则同步。补取请求串行，过期响应不能覆盖随后收到的实时事件；完成、取消或离开任务时关闭连接并取消请求。接口错误区分网络故障、非JSON服务响应和后端业务提示，不自动重放创建任务等写请求；提交结果不确定时提示先检查研究记录。

创建任务支持 `Idempotency-Key`。工作台在提交前立即暂存草稿，并为同一份输入保留提交标识；响应丢失或刷新后，用户再次提交相同输入会返回原任务，不重新执行研究。同一标识不能用于改变后的输入；修改输入、成功提交、新建或清空输入后按新的提交处理。不自动发送重试请求。标识与用于比对的输入副本只暂存在当前标签页，浏览器不允许存储时仅保护当前页面内重试，仍须先检查研究记录。服务端按提交标识确定任务ID，并绑定原始输入指纹；重复创建由数据库唯一主键阻止，运行容量已满时仍可查看原提交结果，已删除记录不能由旧请求恢复。重试研究保留创建标识，但不会因此启动新执行。数据库写入确认丢失时先核对已保存记录；不删除仍被任务引用或暂时无法确认的正文载荷。HTTP请求按完整字节串解码中文，避免分块边界损坏字符。

最终交付先结束阶段快照，再保存正式结果，数据库确认成功后才发布完成事件与正文。保存期间显示“保存中”，暂不开放导出或取消；保存最多尝试3次，两次等待分别为500和1500毫秒，不重新调用模型或数据源。失败后保留当前服务内的待保存结果，详情显示“待保存”及“重试保存”；该操作使用原ID及重试版本，只重新保存原结果，不增加研究重试次数。重复保存请求有互斥与版本检查，成功响应丢失后再次请求会返回已保存记录。保存失败不会把已完成研究误报为审计不通过，原执行失败或取消原因也会随保存保留。尚未保存的内容仅暂存在当前进程，服务重启可能丢失，界面明确提示这一限制；不能声称已持久化或恢复不存在的结果。

首页上手指引与常见问题已补充资料上传、按缺口搜索及离开页面的时机。研究手册新增 `/handbook?tab=guide` 使用指南，按资料准备、来源核对、报告审计和失败恢复四类展开；支持直接链接、刷新与浏览器返回。`/handbook` 仍默认显示研究纪律，术语入口保持不变。操作说明集中在手册，工作台只保留格式限制和当前操作提示。

### V4.2 组合执行纪律同步

V4.2 引入的组合执行纪律继续保留在当前 V4.7 中，新增任务使用第 7 版交付协议。减仓、清空、重新买入或交易复盘任务在原主模式中补充执行记录，复盘及重新买入另列核验章节；Quick 输出范围保持原样。研究动作枚举不变，组合再平衡不自动转为研究退出。没有完整组合信息时仅给条件式框架与缺失项。

相关任务的独立审计须提供 10 项执行纪律检查，逐项记录依据与 passed / limited / not_applicable / failed 状态；缺失、重复或 failed 项阻止交付，不适用必须解释。检查说明参与来源编号校验并显示在审计记录中。程序验证结构与引用，事实和执行条件是否成立仍由模型结合实际证据复核。研究手册同步展示执行纪律及 33 条禁止事项；旧报告保留原规则版本，不自动重写。

V4.2 产品入口：首页组合分析提供减仓与再平衡、清空依据、交易复盘三个问题入口。工作台按问题及用户填写的组合背景补充执行范围，可加入填写提纲；提纲保留已有文字并沿用草稿暂存、刷新恢复和输入复用。手册用六张卡片说明执行纪律，支持从工作台直接定位。

执行审计交付保留原审计全文用于导出，同时保存校验后的检查项、原因、来源编号和独立复核说明。详情将研究判断与组合结论分开；执行复核支持状态筛选、键盘定位与跳转对应证据。历史记录缺少结构化检查项时继续展示原审计正文，不补造检查状态。

### V4.3 估值规则精简

V4.3 基于完整 V4.2，撤除 V4.0→V4.1 增加的市赚率三公式、支付率修正系数、价格锚、行业龙头锚、阶段股票池筛选及相关输出与审计。保留 V4.0 基础框架、V4.1.1 的执行与数据核验规范、V4.2 的组合执行纪律。新任务不再暴露或执行 calculate_p2；新交付不接受市赚率作为估值方法。研究手册保留13个基础术语。

原版本文档及已完成研究记录保留。旧规则版本中断任务重试时，页面说明规则已升级，并按新规则重新研究，避免将旧公式、旧提示词或旧草稿混入 V4.3；同版本任务继续支持断点恢复。完整版本文件与变更说明见 [V4.3 归档](knowledge/versions/v4.3.0/README.md)。

### V4.3 平台同步

首页和手册共用“看懂公司 → 核对价值 → 形成研究判断 → 按约束讨论执行”的方法说明，手册的 `/handbook?tab=method` 展示当前规则与版本变化。工作台先输入问题再确认路径，路径改变会同步交付重点；完整交付范围在侧栏查看。详情保留简要摘要与独立正文，估值依据可直接定位查看；窄屏阅读工具停靠底部，避免挤压正文。历史报告显示记录版本，不替换原始判断。

`shared/valuation-policy.mjs` 向六类研究计划、页面提示与服务端复核提供一致的估值边界。同类倍数变式、DCF 的 FCFF/FCFE 口径和情景变化不计为独立方法，收益率锚不能单独声明内在价值已获支持。新交付拒绝已移除的估值方法，旧报告原文与工具轨迹仍可查阅。续跑核对已固定快照与保存的内容摘要；新任务采用新的有效快照，已绑定任务仍可按原快照恢复。旧记录没有快照且规则发生变化、原快照缺失或损坏时，明确说明后重新研究。

工作台按“问题 → 路径 → 标的 → 设置”定位待处理项；自动匹配期间隐藏未确认的交付范围。旧报告选择区、提交检查与范围摘要共用核对状态；记录加载失败、已删除或标的不匹配时可刷新或取消选择，保留已填写的外部旧结论。规则变更或缺少保存进度的失败记录明确显示重新研究原因，并在新一轮执行记录中保存原因。

同一输入在自动路径重新识别后仍复用未确认提交的原始请求和提交标识，避免刷新生成的新判断编号造成重复任务。服务端先查找原任务，再校验路径判断；只有明确返回判断失效时才清除旧提交标识并重新识别，网络错误不清除。用户再次提交才发起请求，不自动创建研究。

报告、草稿和审计正文中的已关联证据编号支持点击核对，包括并列引用；跳转会清除来源搜索并展开目标资料。来源页提供返回原文入口，恢复阅读位置与键盘焦点；正文、导出内容与原始引用不变。代码、已有链接和未关联的编号不转换，不根据编号猜测来源。引用锚点按正文位置生成，新增来源不会改变已存在引用的返回位置。

### V4.7 快照更新与读取追溯

同一框架版本内，入口、目录和全部模块校验通过后，新任务自动采用新快照；写入未完成或校验失败时继续使用最近有效快照。进行中的任务及可恢复的中断任务固定原快照，草稿、补读、审计和最终来源一致。实际读取记录区分文件检索与上下文章节，保留原因、行号和校验值，随任务与最终报告保存，执行轨迹可查看规则来源。业务正文没有更新，详见 [V4.7 发布说明](knowledge/versions/v4.7.0/README.md)。

### V4.7 平台同步

首页与研究手册统一说明按需使用、任务固定依据和实际读取追溯。首页、手册和工作台展示服务端确认的可用规则；页面切换、重新获得焦点及手动检查会刷新服务状态。连接失败或页面与服务版本不匹配时保留输入并阻止新建研究；待校验修订存在时仍可使用有效快照。

工作台随 MODE B 的简明、标准、完整展开切换规则使用说明；其他专项保留必需流程。详情的“查看研究过程”内提供“本次规则依据”，支持按需补读及审计筛选；实时读取事件仅更新所属快照，重复记录不累加。历史记录未保存的明细显示未记录。窄屏压缩状态区并去除重复正文标题，规则明细放在过程抽屉内，优先呈现报告；首页锚点在初始异步布局变化后校正，用户手动滚动时立即让出控制。

只读接口 `GET /api/jobs/:id/rules?record=<读取记录键>` 从该任务的固定快照还原当时读取的正文；服务端按已保存的记录定位路径与范围，核验文件及内容摘要。快照缺失、记录不匹配或校验失败时明确报错，不用最新文件替换历史原文。Markdown 导出各模式均保留记录版本、快照与实际使用明细，不再将完整模块目录称为本次已使用规则。

验证入口：`node --test tests/research-knowledge.test.mjs`、`node --test tests/knowledge-api.integration.mjs`；浏览器回归可使用 `UI_TEST_FILTER=knowledge-v47` 运行现有界面测试脚本，覆盖桌面与 320px 窄屏、状态恢复、版本不匹配、原文失败重试、历史缺失及实时去重。全部使用合成资料，接口测试使用独立临时数据库。知识正文和 V4.7 归档文件未修改。

V4.7 平台体验优化：详情与手册在访问时加载，资源失败时提供刷新重试和返回首页。服务状态与原文读取设置 10 秒超时，异常响应不会被当作可用服务；模型未配置时明确说明。规则记录支持标题、读取原因与文件名搜索，每批显示 20 条，清除搜索恢复输入焦点；原文收起后在当前记录内保留已读取内容，键盘焦点和展开状态保持一致。上述行为纳入 `knowledge-v47` 浏览器回归。


### 平台 Agent 执行能力对齐

以 Codex 执行研究时使用的能力为参照，平台新增以下实际工具，不展示历史研究案例、不导入案例数字和结论：

- update_research_plan / get_research_status：维护公开执行计划、竞争性解释、步骤引用、失败与剩余预算。完成步骤须关联真实已返回的调用，状态不代表事实已独立核实。
- read_source_pages：对本次已采集官方 PDF 指定物理页码读取，每次最多3页，支持正文分批返回和 Vision 定向转写。重新下载校验原件 SHA-256，内容变化时停止，使用既有官方地址允许列表。每次研究最多16个远程定向页次，失败计入预算；图片仅进入视觉归档，分析上下文和事件中不保存 base64。
- verify_financial_inputs：核对指定正文块中的连续摘录、指标标签与完整带符号数字，支持明确单位缩放；OCR、视觉转写和待核对块不自动成为可计算原数。匹配结果保留行列、期间和币种限制。
- calculate_valuation_snapshot：固定元与股单位，复算匹配累计期的 TTM、市值、PE、PB与显式敏感性，核对行情快照一致性。保留资本变动、EPS代理与假设限制；快筛可使用，不等同于完整估值。
- calculate_cashflow_bridge：解释明确资金流对合并 OCF 的同期变化，保留符号、来源、缺失与未解释差额。诊断余额不是正常化 FCF。

快筛/简明研究24轮，标准研究32轮，完整展开48轮；工具调用和定向页次另有预算。上下文过长时按完整证据块与完整工具返回整理，记录遗漏范围，原执行记录仍保存在任务中。到轮次上限时以已读取据和缺口整理草稿，仍经过独立审计。既有固定规则快照、按需补读和断点恢复继续使用。

首页和手册说明平台真实执行能力，详情呈现公开计划更新、定向取证和实际参数返回。所有路径默认导出完整研究记录，也可选择仅报告、审计与来源；不输出模型私有思维链。运行仍使用已配置的分析/视觉服务，未切换模型供应商。

验证：node --test tests/agent-capabilities.test.mjs tests/cashflow-bridge.test.mjs tests/research-record.test.mjs；浏览器 UI_TEST_FILTER=agent-capabilities-。使用合成资料和模拟模型接口，另测试实际 PDF 指定页读取进程。

进度恢复优化：状态拉取超过 10 秒会释放同步请求，后续可继续恢复；无效状态响应保留当前报告，成功同步后清除连接提示。服务异常或版本不一致时暂停自动路径判断，恢复连接后再按当前问题识别。首页研究流程入口、快筛示例及报告导出范围的界面检查已按当前流程同步。

导出报告先弹出下载选项，选择“完整研究记录”或“报告、审计与来源”后点击“开始下载”；桌面和移动端一致，取消弹层不会下载。报告首屏与宽屏阅读模式的浮动控件检查保留明确的位置约束，等待布局完成后核对，避免把切换过程中的临时坐标当作最终布局。

研究过程保留规则依据、阶段记录与资料覆盖，移除独立公开计划区和重复的执行轨迹跳转按钮。执行轨迹不再设置独立公开计划入口，实际计划更新在对应调用事件中展开查看。同一次调用的输入与返回合并为一条，展开后查看参数、返回和调用编号；未保存的结果明确标注。详细筛选支持搜索、异常及未保存返回，每批显示 20 条，完整导出仍保留原始记录与公开计划。

执行轨迹采用固定工具区与单一列表滚动，宽屏侧栏适当加宽。状态与时间并排显示，工具名称使用可读标签，调用参数按需展开；搜索支持清除和重置，筛选后回到列表顶部，继续加载保留当前位置。调用事件和加载更多位于同一滚动区域，避免外层侧栏与事件列表重复滚动。

工作台六条路径共用设置文案映射，手动选择与自动匹配的开始按钮、就绪提示均按实际路径显示。设置区保留一致布局，分别提供各专项的展开选项；快速筛选的五年历史及股东回报的八年历史明确显示为固定范围。匹配期间暂不显示未确认的设置，切换路径保留已填写背景和可调整的历史范围。

设置区依据 `knowledge/modules/rules/01-mode-a.md` 至 `01-mode-f.md`、`12-portfolio.md` 与 `15-output-dividend.md` 区分输入：深度研究聚焦公司逻辑与估值反证，股东回报聚焦分红、回购、现金来源与用户指定收益率锚；两者的个人持仓约束默认折叠，已有持仓或识别到个人执行问题时展开。组合分析默认展示“持仓构成”和“风险与资金需求”两组字段，并说明信息不足的限制。快筛保持简短关注点，多公司比较提供共同口径下的比较重点，财报更新保留旧报告选择与无旧结论建立基线。关注点按钮仅追加可编辑文本，不覆盖已填内容；收起字段、切换路径和刷新后保留原输入，并沿用 `portfolio` / `portfolioContext` 提交给研究流程。知识正文及计算规则未修改。
