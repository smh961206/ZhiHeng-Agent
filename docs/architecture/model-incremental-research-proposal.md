# M1.2 增量研究与依赖图具体方案

状态：规划稿
前置版本：M1.1 Token-efficient stage contexts
适用基线：V5.2 核心能力 + M1.0 模型管线 + M1.1 环节上下文
计划轨道：M-Series，不占用 Knowledge Engineering 的核心版本号

## 1. 定位

M1.1 解决一次研究任务内部重复发送规则、工具记录和证据的问题。M1.2 进一步解决同一任务不同环节、同一证券后续研究以及财报更新反复研究相同内容的问题。

M1.2 的核心是建立可验证的依赖关系：

```text
Evidence
  → Verified Fact
  → Deterministic Calculation
  → Claim
  → Report Section
  → Decision View
```

模型只处理新增、变化、冲突或失效的节点。报告继续是结构化研究状态的视图，不能反过来成为规范事实。

## 2. 目标

- 财报更新只分析新期间、新披露和受影响的结论；
- 相同原件、解析结果和确定性计算可以安全复用；
- 未受影响的研究节点不重复调用模型；
- 事实、计算、推断、预测和决策保持不同语义；
- 重述、修订、数据截止日和历史原报数据不被覆盖；
- 跨任务复用不能把未来资料带入历史时点；
- 不增加 Token 预算、模型晋级、A/B、付费试跑或验收文件；
- 研究效果优先于 Token 指标。

## 3. 不在本版本处理的内容

- 自动交易或仓位执行；
- 分布式 Agent 或多节点队列；
- 用向量相度替代证券身份、期间和财务字段精确匹配；
- 从报告正文反向抽取并覆盖规范事实；
- 自动接受模型生成的财务数字；
- 跨证券、跨股类或跨会计范围的模糊复用；
- 因成本、Token 或资料缺失自动切换模型。

## 4. 核心对象

所有对象必须拥有稳定身份、研究截止日、来源谱系和版本。以下为规划合同，实施前需通过 ADR 和正式领域合同。

### 4.1 EvidenceNode

指向现有证据块，不复制或重写原文：

```json
{
  "id": "E:sourceHash:blockId",
  "sourceId": "S12",
  "sourceHash": "sha256",
  "blockId": "page-86-table-1",
  "publishedAt": "2026-03-28",
  "reportPeriod": "2025FY",
  "securityId": "CN:002594",
  "method": "pdf-native",
  "verification": "eligible"
}
```

EvidenceNode 只能引用本次任务可访问的实际来源。搜索摘要、目录页、损坏文本、模糊引用和未经核对的 OCR/Vision 内容不能伪装为已验证财务证据。

### 4.2 FactNode

保存已核验事实的结构化表达：

```json
{
  "id": "F:security:concept:period:basis:revision",
  "kind": "verified-fact",
  "securityId": "CN:002594",
  "concept": "revenue",
  "period": "2025FY",
  "currency": "CNY",
  "unit": "million",
  "accountingScope": "consolidated",
  "shareBasis": null,
  "value": 777102,
  "evidence": ["E:..."],
  "publishedAt": "2026-03-28",
  "validAtCutoff": true
}
```

缺失事实保持缺失。预测、模型推断、第三方估计或模糊识别不能写成 `verified-fact`。

### 4.3 CalculationNode

保存程序计算及其完整输入依赖：

```json
{
  "id": "CALC:normalized-earnings:hash",
  "kind": "deterministic-calculation",
  "formulaVersion": "normalized-earnings-v1",
  "inputs": ["F:...", "F:..."],
  "result": {},
  "basis": {
    "period": "2025FY",
    "currency": "CNY",
    "shareBasis": null
  }
}
```

输入事实、公式版本或口径变化后，旧计算保留但标记为不再适用于新视图，不能原地改写。

### 4.4 ClaimNode

主张明确区分观察、推断和预测：

```json
{
  "id": "C:hash",
  "kind": "inference",
  "text": "库存增长可能反映需求放缓",
  "supports": ["F:...", "CALC:..."],
  "counters": ["F:..."],
  "missing": ["G2"],
  "confidence": "medium",
  "status": "supported-with-limitations"
}
```

模型可以提出 Claim，但程序必须验证引用的节点真实存在、属于相同证券和允许时点。模型不能创建 Fact 或 Calculation。

### 4.5 SectionNode

报告章节引用 Claim，而不是复制整个研究上下文：

```json
{
  "id": "SECTION:financial-trend",
  "templateVersion": "deep-research-v1",
  "claims": ["C:1", "C:3"],
  "renderedMarkdown": "...",
  "dependencyHash": "sha256"
}
```

Claim 或模板没有变化时，章节可以复用。章节中引用、数字和缺失清单仍需重新执行确定性校验。

### 4.6 ResearchSnapshot

ResearchSnapshot 固定某个研究时点可用的节点集合：

```json
{
  "version": 1,
  "researchId": "uuid",
  "cutoff": "2026-09-13",
  "knowledgeVersion": "4.7",
  "securities": ["CN:002594"],
  "evidence": [],
  "facts": [],
  "calculations": [],
  "claims": [],
  "sections": [],
  "missing": [],
  "dependencies": []
}
```

快照属于结构化研究状态。报告、审计文本和最终判断是该快照的视图。

## 5. 稳定身份与复用条件

### 5.1 证据可以复用的条件

必须同时满足：

- 证券稳定身份相同；
- 来源原件哈希相同；
- `publishedAt` 不晚于新任务截止日；
- 报告期和披露身份一致；
- 解析版本兼容；
- 块身份仍能唯一定位；
- 来源没有被标记为损坏、截断或身份冲突；
- 新任务拥有读取该资料的合法范围。

### 5.2 事实可以复用的条件

除证据条件外，还要求：

- concept、期间、币种、单位和会计范围完全一致；
- 股本和估值相关事实的股类及 share basis 一致；
- 没有被后续重述替代；
- 新任务明确接受原报值或最新重述值的对应语义。

### 5.3 计算可以复用的条件

- 所有输入 Fact 身份相同；
- 公式版本相同；
- 参数、情景和估值基准相同；
- 没有输入缺失或冲突状态变化；
- 结果仍能从输入重新计算得到。

### 5.4 Claim 可以复用的条件

- 所有支持、反证和缺失依赖没有变化；
- Claim 类型和问题范围相同；
- 研究时点允许；
- 没有新增足以影响该主张的反证；
- 置信度仍符合当前证据覆盖。

旧 Claim 只能作为待复核研究状态，不能因依赖哈希相同就跳过最终 Auditor。

## 6. 依赖失效算法

新增资料进入后按以下顺序处理：

```text
1. 规范化证券身份和披露身份
2. 计算原件及证据块哈希
3. 与当前快照比较新增、修改、重述、失效和未变化节点
4. 从变化的 Evidence 向后遍历依赖边
5. 标记受影响的 Fact、Calculation、Claim 和 Section
6. 只重算受影响的确定性计算
7. 只把受影响 Claim 交给 Researcher
8. 只重写受影响 Section
9. 对完整最终报告重新执行确定性校验和 Auditor
```

失效原因至少包括：

- `new-evidence`：新增资料；
- `source-revision`：相同披露的修订版；
- `fact-change`：同口径事实变化；
- `basis-change`：币种、单位、期间、范围或股本口径变化；
- `formula-change`：计算公式版本变化；
- `counter-evidence`：出现新的反证；
- `knowledge-change`：适用的规则版本变化；
- `cutoff-incompatible`：节点不属于当前研究截止日；
- `source-invalid`：原件损坏、截断或身份不再可信。

## 7. 财报更新流程

财报更新优先使用差异研究：

```text
原研究快照
  + 新财报/公告/结构化数据
  ↓
确定性差异检测
  ↓
变化事实 + 新反证 + 新缺口
  ↓
受影响计算
  ↓
受影响主张
  ↓
受影响章节
  ↓
完整报告校验与审计
```

模型收到的差异包：

```json
{
  "previousCutoff": "2026-06-30",
  "currentCutoff": "2026-09-13",
  "newEvidence": [],
  "changedFacts": [],
  "restatements": [],
  "affectedCalculations": [],
  "affectedClaims": [],
  "unchangedClaimIds": [],
  "newMissingData": [],
  "resolvedMissingData": []
}
```

“缺失已解决”必须关联实际新增证据。没有新证据时，模型不能自行删除旧缺口。

## 8. 六条研究路径的差异化执行

### 快速筛选

- 程序生成估值、盈利、现金流和风险指标；
- 模型只解释异常、限制和条件性判断；
- 表格、来源和缺口由程序渲染。

### 深度研究

- 以 Claim、支持证据、反证和证伪条件为核心；
- 未变化 Claim 可以复用为待审状态；
- 受影响 Claim 重新研究，最终报告完整审计。

### 财报更新

- 以新旧期间差异、重述和受影响节点为核心；
- 不重复分析未变化的业务背景；
- 原结论和新结论并列，明确变化原因。

### 多公司比较

- 先建立统一期间、币种、单位和估值口径的比较矩阵；
- 每家公司独立计算；
- 只重算发生变化的公司和比较维度；
- 不能用一家公司的资料填补另一家缺口。

### 组合分析

- 程序计算持仓权重、行业集中、现金和流动性等结构；
- 模型分析组合暴露、相关风险和反向情景；
- 缺少真实持仓时不输出具体仓位建议。

### 股东回报

- 程序维护分红、回购、注销、股本变化和归属年度账本；
- 新事件只更新受影响年度和资本配置主张；
- 提案、实施、付款和未来计划保持不同状态。

## 9. 确定性报告生成

以下部分由程序生成：

- 财务与估值表格；
- 同比、环比、利润率和现金流桥接；
- 来源目录和引用脚注；
- 计算方法、期间、币种、单位及股本口径；
- 缺失数据和未解决冲突清单；
- 数据截止日和资料覆盖；
- 已完成工具及审计检查摘要。

模型负责商业解释、竞争性解释、反证、风险和条件性结论。模型文本不能修改程序生成的数字或删除缺口。最终渲染器把确定性区块和模型章节组合成报告，再运行现有交付校验。

## 10. 主张级审计

Auditor 先检查 ClaimNode：

- 类型是否正确；
- 支持证据是否真的支持主张；
- 是否存在未处理反证；
- 计算是否使用相同口径；
- 缺失信息是否降低结论强度；
- 预测或假设是否伪装成事实；
- 研究截止日是否有效。

随后检查完整报告：

- 章节是否完整；
- 每项重要判断是否能回到 Claim；
- 每个数字是否能回到 Fact 或 Calculation；
- 引用、缺口和结论是否一致；
- 程序生成区块有没有被模型文本覆盖。

## 11. 紧凑模型输入

多期、多公司数据使用带字段字典的列式表达：

```text
字段: period | revenue_CNY_m | net_profit_CNY_m | source
2025FY | 777102 | 40254 | S2:b8,S2:b12
2024FY | 602315 | 31344 | S5:b6,S5:b9
```

紧凑表达只用于模型输入。后端继续保存结构化原值、期间、单位、来源和转换记录。空值写为 `null`，不能省略后让模型猜测。

## 12. 预计代码归属

优先扩展现有模块：

| 现有 owner | 规划职责 |
| --- | --- |
| `server/evidence-search.mjs` | 证据块稳定身份和精确加载 |
| `server/financial-observations.mjs` | 事实期间、口径、修订与来源语义 |
| `server/calculations.mjs` 及现有计算模块 | 计算输入和公式版本依赖 |
| `server/research-context.mjs` | Claim/Section 所需上下文投影 |
| `server/research-output.mjs` | 确定性区块与模型章节组合 |
| `server/research-resume.mjs` | 快照及依赖版本恢复 |
| `server/model-telemetry.mjs` | 增量任务的调用和 Token 归属 |
| `server/storage.mjs` | 新旧研究状态双读和新增写入 |

依赖图若需要独立 owner，必须先接受 ADR，明确它只维护节点关系，不复制 Evidence、Fact、Calculation 或报告系统。

## 13. 分阶段实施

### M1.2.0：对象与身份 ADR

- 明确 Evidence、Fact、Calculation、Claim、Section 和 Snapshot 合同；
- 定义稳定身份、时点语义、重述和失效原因；
- 只写文档和架构测试，不改变运行路径。

### M1.2.1：只读依赖清单

- 从现有任务构建临时依赖清单；
- 不改变报告和模型请求；
- 比较清单是否覆盖现有引用和计算依据。

### M1.2.2：ResearchSnapshot 加法写入

- 新任务在现有结果旁保存结构化快照；
- 旧读路径继续有效；
- 不回填、不覆盖历史任务。

### M1.2.3：确定性差异检测

- 对相同证券的新旧快照生成差异包；
- 保留新增、修订、重述、冲突和缺失；
- 暂不改变模型调用。

### M1.2.4：财报更新增量执行

- 财报更新只重算受影响 Calculation；
- Researcher 只处理受影响 Claim；
- Writer 只更新受影响 Section；
- Auditor 仍检查完整报告。

### M1.2.5：确定性报告区块

- 程序生成数据表、来源、计算和缺口区块；
- 模型不再重复输出这些内容；
- 渲染后执行现有引用和交付校验。

### M1.2.6：其他研究路径增量化

- 依次覆盖快速筛选、多公司比较、股东回报、组合分析和深度研究；
- 每条路径独立验收和回滚。

### M1.2.7：主张级审计

- Auditor 检查 Claim 和完整报告；
- Critical Reviewer/Judge 继续使用现有资格与独立上下文；
- 不降低最终审计次数。

### M1.2.8：跨任务安全复用与效率报告

- 开启满足全部身份和截止日条件的复用；
- 展示新增、复用、失效和重算节点数量；
- 按研究路径统计正常任务 Token，不增加预算配置。

## 14. Schema 与迁移策略

这是持久化 Schema 变化，必须使用：

```text
加法 Schema
→ 旧读 + 新读
→ 新任务写新结构
→ 验证式可选回放
→ 新视图切换
→ 兼容窗口后再评估清理
```

具体要求：

- 不修改已有 Evidence、研究记录和报告；
- 不对旧任务做未经验证的自动回填；
- 不从旧报告正文推断 Verified Fact；
- 新 Snapshot 与原任务、截止日和模型状态绑定；
- 历史原报值与后续重述同时保留；
- Mongo 新字段或集合采用可选加法结构；
- 索引建立失败不得破坏旧读路径；
- 回滚后新增字段保持可忽略。

## 15. Token 与质量目标

在 M1.1 达标基础上，以正常研究的供应商实际用量观察：

| 路径 | M1.2 总 Token 降低目标 |
| --- | --- |
| 首次深度研究 | 40%–55% |
| 财报更新 | 60%–80% |
| 快速筛选 | 30%–50% |
| 多公司比较 | 40%–60% |
| 组合分析 | 35%–55% |
| 股东回报 | 45%–65% |

目标不可相加，样本不足时保持未知。以下质量指标不能下降：

- 有效引用率；
- 计算可复现率；
- 报告期间、币种和股本口径完整率；
- 反证覆盖率；
- 缺失数据保留率；
- 确定性校验通过率；
- 最终交付率；
- 恢复后无重复调用率。

## 16. 必测场景

- 新财报只失效相关事实、计算、主张和章节；
- 后续重述不覆盖历史原报数据；
- 历史截止日不能读取未来发布资料；
- 同证券不同股类不能错误复用估值和股本；
- 同报告期不同币种、单位和会计范围不能合并；
- 缺失、零值和负值保持不同语义；
- 新反证强制失效相关 Claim；
- 未变化依赖不会重复运行模型；
- 程序生成数字不能被 Writer 修改；
- Auditor 收到完整最终报告；
- 跨任务复用仍能追溯到原件和块；
- 断点恢复不会重复计算或模型调用；
- 删除原研究后共享证据的引用完整性仍可验证；
- API 不泄露私有快照、隐藏推理或完整内部依赖图。

## 17. 配置变化

M1.2 不增加用户配置项。模型继续由 `MODEL_CONFIG_FILE` 的八个环节分配，Token 继续由 `MODEL_TELEMETRY_ENABLED` 记录，价格继续由可选 `MODEL_PRICING_FILE` 估算。

增量逻辑由研究路径、任务状态、证据身份和代码版本决定，不提供“复用多少”“最多多少 Token”或“按价格跳过审计”等用户开关。

## 18. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 错误复用旧事实 | 精确证券、期间、币种、范围、股本和来源身份 |
| 新反证没有触发更新 | 反证是 Claim 的一等依赖边 |
| 重述破坏历史研究 | 原报值追加保存，按 cutoff 选择视图 |
| 报告章节复用后引用失效 | 每次交付重新运行完整引用校验 |
| 模型文本污染规范状态 | 模型只能写 Claim/Section 草稿，不能写 Verified Fact |
| 依赖图成为第二事实系统 | 只保存关系和身份，事实仍由现有领域 owner 管理 |
| Token 指标驱动错误裁剪 | 所有质量门槛优先，未知数据不计为节省 |

## 19. 回滚

每个子版本必须可独立回滚：

1. 保留新增 Snapshot 和依赖记录；
2. 切回旧的完整研究路径；
3. 旧代码忽略新增可选字段；
4. 不删除证据、事实、计算、报告、调用收据或历史重述；
5. 已开始的增量任务由相同代码和快照版本完成；
6. 不通过删除检查点强制重新调用模型；
7. 回滚后执行全量、发布、Mongo、恢复、时点和页面回归。

## 20. 推荐启动范围

第一阶段只实施 M1.2.0–M1.2.3：先完成合同、只读依赖清单、加法快照和差异检测，不改变模型调用。确认依赖图能够完整解释现有报告引用、计算和缺口后，再授权 M1.2.4 财报更新增量执行。

财报更新是首个运行场景，因为输入边界、前后期间和变化范围最明确，节省空间也最大。其他研究路径必须在财报更新稳定后分别实施，不能一次性切换全部路径。
