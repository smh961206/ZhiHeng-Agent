# Release Process

1. Read CURRENT.
2. Inspect current code.
3. Run baseline tests.
4. Implement one subrelease at a time.
5. Keep repository runnable.
6. Add tests/architecture fitness checks.
7. Run release benchmark.
8. Verify migration/rollback.
9. Produce completion report.
10. Change CURRENT only after acceptance and explicit user direction.

Never combine multiple major releases in one uncontrolled change.
