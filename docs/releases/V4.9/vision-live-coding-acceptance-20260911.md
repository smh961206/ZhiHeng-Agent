## 失败案例复核

- 候选 VIS-012、VIS-030：扫描原件及完整脚注均使用 `[1]`，两侧 Liabilities 单元格却返回 `footnote: "1"`，共四个标记与参考不一致。数值和期间读取正确，但未满足原样保留标记的约定。
- 基线 VIS-016、VIS-023、VIS-030、VIS-042：把原件中的通用缺失说明／合成语料声明加入 footnotes 列表。那些文字确实存在于图片中，属于提取范围不符合约定，并非凭空生成财务事实。
- 基线 VIS-033、VIS-034、VIS-036：将图片的 unreadable 文字直接放入 value，正确结构应为 null。候选在这三例均返回 null；本轮未发现候选把缺失值补成零。

已逐图核对全部失败原件，并抽看其他覆盖单位、期间、负数、百分比、空白、不可读、零值与三种格式的样本。本轮共查看 25 份原件／渲染页，不声称已完成操作人对全部 48 份的人工批准。48 例两侧输出均独立重新评分，原分数与复算一致；完整逐项表和字段差异在 artifacts/vision-live-glm53-coding-20260911-case-review.md。

本批次完整性、96 条完成账本、逐结果哈希、语料原件与双方同图检查通过；运行结束与复核时配置／源码绑定均一致。无 reserved 遗留，新批次锁正常释放。服务器准入检查仍返回 operator_review_required、critical_quality_regression。原始比较 reportHash：b68fec889587d3205df338a382c57f49facdc8734bed639080e8d9e562417aff。

## 运行边界

本轮使用既有冻结 48 原件（16 表格、16 截图、16 扫描 PDF）及原有 Gateway、生产渲染和严格评分。基线 deepseek-flash 使用 https://api.deepseek.com；候选 glm-5.3-flash／zai 在本轮进程中指定 https://open.bigmodel.cn/api/coding/paas/v4，INPUT=images、THINKING=omit。读取本地现有密钥，没有持久修改环境文件、生产配置或私有凭据。

候选单次诊断已返回 HTTP 200 和真实表格输出，之后开始 96 次比较调用。预检额外一次，本轮最多安排 97 次逻辑调用。原生网络层的连接故障重试仍属于现有 Gateway 行为，请求数统计不等于供应商账单证明。临时执行包装器仅提供进程级地址覆盖、人工停止文件和连续三次服务错误停止；不会改变模型请求、答案或评分。

本轮 96 次比较与 1 次预检全部返回结果，程序正常结束。生产 FEATURE_VISION_ROUTING 保持关闭，未生成操作人批准文件。
