# V5.0 本地与生产高级配置拆分

> 历史记录：此布局已被 2026-09-11 的单环境文件归并取代，当前启动不再加载 `.env.models` 或 `.env.production.models`。

按用户确认，将本地配置拆为 `.env` 与 `.env.models`，生产配置拆为 `.env.production` 与 `.env.production.models`。本次实现文件拆分与加载，不执行此前提出的模型定义归并方案。

两份原实际配置各有 40 个键，拆分后各为基础 25 个、高级 15 个。依据 `.env.models.example` 的现有高级字段集合迁移，逐项保留赋值原文，合并后的全部解析值与原文件相同。没有增加未配置的候选或 A/B 字段。

## 加载与兼容

本地开发后端和已有带环境加载的包命令使用 Node 原生参数，先读取 `.env`，再读取可选 `.env.models`。生产 Compose 先注入必需的 `.env.production`，再注入可选 `.env.production.models`。未拆分的旧部署仍能只使用基础文件。

Node 中进程已有变量优先于文件；文件之间后读覆盖先读。Compose 中后列文件覆盖先列文件，显式 environment 继续优先。实际拆分结果无跨文件重复键。用户后续修改时也应让同名键仅保留一处。

生产宿主机绑定地址、映射端口等插值参数继续从基础文件读取；高级文件只存模型相关设置。Compose 的可选 env_file 需要 2.24.0 或更新版本。本次通过已安装的 Compose v5.5.1 解析验证，没有启动容器。

`.env.models.example` 仍是参考模板，可分别摘取为对应环境的实际高级文件，示例自身不加载。Git 与 Docker 构建忽略实际环境文件。配置修改后需重启进程或按生产部署流程重建应用容器；本次未重启任何正在运行的服务。
