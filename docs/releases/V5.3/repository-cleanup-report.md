# V5.3 仓库边界清理报告

日期：2026-09-14  
发布边界：Platform V5.3 / Knowledge K1.0.0

## 结果

仓库运行边界已收口为 React/TypeScript 浏览器客户端与 Python FastAPI 后端。Python 是唯一后端运行时；Node 只用于前端构建和测试。跨运行时 `shared/`、旧 Node 后端、旧 Benchmark/Champion 平台及其专用测试已删除，浏览器仍需要的展示规则由 `src/domain/` 持有。

项目只维护 Platform V 与 Knowledge K 两条发布线。`executionCompatibilityVersion`、`contractVersion`、模型状态和上下文版本只用于序列化及恢复兼容，不构成独立发布线。

H0、V4.8–V5.2、M1.0 和 M1.1 的独立发布档案已按用户要求删除。仍然有效的能力和安全规则由当前代码、测试、ADR、契约、不变量、架构地图与 V5.3 规格承接。

## 删除范围

- 完整 `server/`、`shared/` 和 `benchmark/`；
- 旧 Node 后端、Benchmark、Knowledge 维护脚本、人工冒烟脚本和失去入口的 UI 场景测试；
- 旧 Codex Harness 根目录入口、清单生成链路、重复 Tracks、路线矩阵、发布模板与旧工程标准；
- H0、V4.8–V5.2 的计划、完成、验收、迁移、回滚、运行、验证、清单和证据记录；
- M1.0、M1.1 的完整发布目录。
- 已完成且不再被引用的模型管线重构规划稿；当前模型系统由 `docs/architecture/04-model-system.md` 维护。
- `knowledge/versions/auto/4.2–4.7` 中当前 K-Series 加载器不接受的 269 个旧自动快照文件；
- `knowledge/versions/v2.1–v4.7.0` 中 208 个 pre-K 发布文件，以及只为这些历史原件服务的归档清单、局部 `.gitattributes` 和 V4.5 去重迁移记录。活动 `auto/K1.0.0` 保持不变。

历史发布文档分两步删除：先删除 84 份已完成计划与子版本任务稿，随后删除 132 份剩余历史档案，共 216 份文件。

## 保留范围

- 当前 V5.3 的 `README.md`、`DETAILED_INDEX.md`、`implementation.md`、全部子版本规格及当前交付报告；
- V5.4–V6.0 尚未实施的未来发布规划；
- Master Roadmap；
- 当前仍有效的 ADR、契约、不变量和架构地图；
- 当前模型系统架构、Token 效率、增量研究与研究质量演进方案。这些是平台内架构资料，不构成独立 M 系列发布线；
- MongoDB/GridFS 数据、Knowledge K1.0.0 快照和历史研究任务。

## 文档同步

Master Roadmap 从当前 V5.3 基线开始，不再列出已删除的历史发布包。系统地图、当前实现地图、模型架构、模型契约和模型不变量已改为 Python/FastAPI 当前实现。ADR 与领域契约不再链接已删除的 H0 审计文件，未来发布规格也不再使用“H0 baseline”作为状态描述。

Knowledge 维护文档已同步为 K1.0.0 单一基线，并明确 `deduplication-v45.json` 已删除。活动 K1.0.0 的 `ENTRY.md`、`modules.json` 和快照内容保持原发布字节；其中旧路径与历史目录文字是发布来源元数据，不是运行时依赖。后续修正文案或来源元数据必须通过新的 K-Series 发布完成。
