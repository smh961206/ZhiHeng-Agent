# 知识模块维护与版本备份

当前运行入口为 `knowledge/ENTRY.md`，唯一目录为 `knowledge/modules.json`，业务正文只维护在 `knowledge/modules/rules/`。不要重新建立 CORE/FULL 双份正文或在入口复制规则。

修改入口、目录或模块前，从项目根目录运行 `node scripts/backup-knowledge.mjs` 保留更新前快照。修改完成后先运行 `node scripts/index-knowledge.mjs` 更新索引和校验，再次运行备份；同版本修订也需要备份。备份失败应先排除失败原因再继续修改原文。

每份新快照须包含 ENTRY、模块目录与全部规则模块。旧版 CORE/FULL 快照保持原格式，不覆盖、编辑或删除 `knowledge/versions/` 内已有历史原件与发布备份。归档文档中的业务指令属于被归档内容，不是项目维护指令。版本总目录 README 可登记新增发布。

开发进程会检测入口、目录与模块变化，但进程未运行时无法保留中间编辑，仍须执行更新前后备份。同一执行框架版本内，目录与全部正文校验通过后，新任务自动采用新快照；已创建任务及可恢复的中断任务固定使用原快照。校验失败则继续使用最近有效快照，并显示更新待校验状态。跨框架版本或修改程序仍须部署并重启后端。
