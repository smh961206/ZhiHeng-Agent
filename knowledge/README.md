# K1.0.0 单一规则知识库

当前维护结构为一个执行入口、一份模块目录和 36 个专项规则文件。

| 路径 | 职责 |
| --- | --- |
| [ENTRY.md](ENTRY.md) | K1.0.0 版本信息与加载说明 |
| [modules.json](modules.json) | 唯一模块目录、章节、检索摘要、治理元数据与 SHA-256 |
| `modules/rules/` | 唯一业务规则正文 |
| [current.json](current.json) | 唯一活动 K-Series 版本及快照指针 |
| `versions/auto/K1.0.0/<snapshot-id>/` | 当前不可变运行快照 |

## 当前基线

K1.0.0 是仓库保留的第一个 Knowledge 发布版本。早于 K1.0.0 的发布目录、自动快照、归档清单和迁移记录已按用户要求删除。`deduplication-v45.json` 已随旧迁移记录删除。

K1.0.0 的 `ENTRY.md`、`modules.json` 和活动快照属于同一份已发布内容，必须保持字节与指纹一致。其中的“历史发布目录”表述及旧 `origin.path` 值是发布时固化的说明和导入来源标签，不是运行时文件依赖，也不表示相应历史文件仍存在。需要修正文案或来源元数据时，应发布新的 K-Series 版本，不能原地改写 K1.0.0。

后端接纳快照前校验 ENTRY、目录、全部规则模块和清单摘要。新任务从 `current.json` 解析活动版本并固定具体快照；研究、补读、审计和恢复均读取该固定副本。活动快照缺失或校验失败时必须停止，不能用工作目录内容替换。

## 按需加载

任务按主模式和研究深度读取所需规则。未加载的详细章节只提供候选标题，需要使用时必须读取原文。执行输出、作战图、组合、股东回报和复盘规则按任务触发；复核阶段读取审计模块。

每次实际读取记录文件、小节、行号、触发原因、快照编号及内容校验值。截断内容不能冒充完整章节，完整性扫描也不能冒充任务已经读取全库。

## 维护

1. 修改前运行 `pnpm knowledge:backup` 验证当前快照。
2. 只修改 `modules/rules/` 中的唯一正文；新增模块先登记到 `modules.json`。
3. 内容变化使用新的 K-Series 版本，不原地改写 K1.0.0。
4. 运行 `python -m pytest python_tests/test_knowledge.py` 和当前发布测试。
5. 运行 `pnpm knowledge:backup` 生成候选快照。
6. 审核通过后运行 `pnpm knowledge:activate` 原子切换活动指针。
