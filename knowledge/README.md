# V4.7 单一规则知识库

当前维护结构为：**一个执行入口＋一份模块目录＋36 个专项规则文件**。不再同时维护 CORE 精简正文和 FULL 完整正文。

| 文件 | 职责 |
| --- | --- |
| [ENTRY.md](ENTRY.md) | 版本信息与加载说明，不重复公式、评分或判断规则 |
| [modules.json](modules.json) | 唯一模块目录：路径、章节、来源、检索摘要和 SHA-256 |
| modules/rules/ | 唯一业务正文，涵盖定位、任务路由、数据、基本面、财务、股东回报、估值、决策、组合、输出与审计 |
| [去重迁移记录](deduplication-v45.json) | CORE 归并去向、独有约束及逐项修改依据；仅供追溯，不加载为业务规则 |

## V4.5 归并基线

以 V4.4 的 FULL 专项作为正文基线，保留详细规则；CORE 的同义缩写引用对应专项，独有约束迁入同一文件。12 项约束明确迁入，另有 2 项元数据/历史说明整理；章节编号、公式、评分权重、六类研究模式和第 7 版交付协议保持原有含义。

旧 CORE/FULL 入口及双份模块已从运行目录移除，完整保留在 [V4.4 快照](versions/v4.4.0/README.md)。历史章节说明不进入当前提示。V4.5 是一次规则去重，与 V4.4 的逐字拆文件不同，不宣称与旧版正文逐字一致。

## 按需加载

后端接纳规则快照前校验 ENTRY、目录、全部模块及章节索引；任务根据主模式从固定快照按需读取专项正文并注入上下文。快筛仅读取估值方法匹配与相对估值部分；普通深度研究仅读股东回报基础部分，完整八年流程由股息专项触发。路由、输出模板按模式选择；组合、执行复盘和作战图按任务触发。复核阶段读取唯一审计模块。

V4.6 对 MODE B 的初始正文按现有交付深度分级：Quick 加载核心基本面与估值快照协议；Standard 加载完整基本面及非 DCF 估值协议；Deep 加载完整估值细则和评分。数据、财务、风险、决策和置信度约束各深度均保留。省略的详细章节仅提供补读标题，需要使用时先读取原文；其他专项继续保留必需流程。

执行输出说明独立保存为 15-output-execution.md；作战图仅在用户要求作战图、估值图或买入区间图时加载，同时补齐评分依赖。两者可分别触发，也可同时触发。所有业务正文与 V4.5 一致，仅拆分一个文件，详见 [V4.6 发布说明](versions/v4.6.0/README.md)。

详细规则查询先定位标题或候选文件，再读取并核验正文，返回真实文件路径和行号。读取过的正文在单个任务会话中缓存，任务间不共享读取记录。完整模块清单用于版本追溯，不表示单次任务已使用全部正文。

## V4.7 快照与实际读取记录

任务创建时固定快照，草稿、规则补读和审计均读取同一副本。同一框架版本内，后续完整更新自动供新任务使用；未完成写入、索引不一致或版本不兼容不会覆盖有效快照。重启时可回退到已校验的完整自动快照。中断续跑使用已保存的原快照；旧记录缺少快照且规则发生变化时，仍重新研究。

每次实际读取记录文件、小节与行号、触发原因、快照编号、文件校验值及实际内容校验值。文件打开与进入上下文的内容分别标记，截断内容不冒充完整章节，重复读取去重；校验阶段扫描全库不记为单个任务使用了全库。记录随任务、检查点保存时的任务状态和最终报告保留，执行轨迹可展开查看章节来源。

自动快照只保存知识规则，不代表执行程序也能热更新。业务正文与 V4.6 完全一致，详见 [V4.7 发布说明](versions/v4.7.0/README.md)。

## 维护

1. 修改前运行 `node scripts/backup-knowledge.mjs`。
2. 只修改 `modules/rules/` 中对应的唯一规则正文；新增模块先登记到目录，不在 ENTRY 另写简版。
3. 运行 `node scripts/index-knowledge.mjs` 更新章节、检索索引和校验值。
4. 再次备份。同一框架版本内，新任务自动采用校验通过的快照；跨框架版本或程序更新后重启后端。

快照覆盖 ENTRY、目录与全部模块。已有发布快照不得覆盖。去重迁移脚本 `scripts/deduplicate-knowledge-v45.mjs` 仅用于从未迁移的 V4.4 升级，拒绝覆盖已有 V4.5。
