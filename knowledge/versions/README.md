## 与项目运行文件的关系

项目运行时读取 [执行入口](../ENTRY.md) 和 [模块目录](../modules.json)，按需读取 knowledge/modules/rules/ 下唯一专项正文，当前同步至 V4.7。发布目录用于历史备份和版本对照，不参与当前正文选择；V4.7 起，auto 下校验通过的不可覆盖快照供已绑定任务按需读取。归档文件中的指令属于版本文档内容。

## 完整性与后续归档

[manifest.json](manifest.json) 记录首次归档的11份原始文件的相对路径、字节数和 SHA-256。后续生成的发布版本使用各自目录中的清单。归档时已逐一与源文件校验一致。目录内的 `.gitattributes` 禁止 Git 自动转换原始 SKILL 文件的换行符，以便检出后仍可按字节核对。

后续版本使用新目录保存，保留旧版本原件，并补充版本关系和校验清单。

## 自动备份

自动快照保存在 `auto/<文件版本>/<内容摘要>/`。V4.5 起每份快照包含 `ENTRY.md`、`modules.json`、全部模块与独立 `manifest.json`；V4.4 快照仍保留 CORE/FULL 索引格式，记录归档时间、各文件版本、字节数和 SHA-256。相同内容重复执行不会新增备份；同一版本号下的内容修订保留为不同快照。CORE/FULL 正在跨版本更新、版本号暂不一致时归入 `auto/mixed/`，不冒充完整发布版本。

- `pnpm dev`：启动前备份，运行期间自动检测入口、目录与全部模块的变化，待写入稳定后再次备份。
- `pnpm build`：执行前检查并备份当前内容，备份失败时停止构建。
- `pnpm start`、`pnpm dev`：由快照管理器校验并备份；当前修订不可用时回退到已校验快照，没有有效快照才阻止启动。
- `pnpm knowledge:backup`：随时手动备份；也可直接运行 `node scripts/backup-knowledge.mjs`。
- `node scripts/backup-knowledge.mjs --watch`：单独启动持续检测，退出进程即停止。

维护者应在修改前、修改后各执行一次备份，详见 [维护约定](../AGENTS.md)。开发进程未运行时不能捕获每次中间编辑；下次启动或构建会备份当时的内容。已有桌面原件归档与清单保持独立，自动快照不会覆盖它们。
