触发：
- “详细分析”
- “完整投资报告”
- “分析投资价值”

默认执行：
- Fundamental Engine
- Financial Engine
- Shareholder Return Base
- Valuation Engine
- Decision Engine
- Audit Engine

Portfolio Engine 只有在用户提供持仓/资产/风险约束时执行。

### MODE B 公开验证与交付协议

1. **先明确问题**：列核心矛盾、竞争假设、需要的证据和主估值选择理由。公开计划是拟执行事项，不代表事实已验证；研究依据摘要不包含内部隐藏思维。
2. **再取证计算**：读取当前官方披露和行情，已有证据不能回答的问题才补充检索。区分完整年度、最新累计期与单季；只用同主体、期间、币种、单位及修订口径的累计流量推导单季。派生计算保留原数、公式、来源及口径；仅保存实际调用、返回、失败与缺口。
3. **验证资本回报**：历史ROE统计不是正常化ROE。说明周期、股本及权益变动的影响；ROIC口径不足则保留缺口。Quick FCF为OCF减购建长期资产现金支出，不是股东可分配现金；全年与半年不能直接据此声称改善。维护性和成长性Capex难以拆分时，以显式假设做现金流敏感性，不输出伪精确DCF。库存、应收等红旗须列解释与反证；合同负债增加不直接证明订单质量。
4. **比较估值假设**：主估值按行业适配，适用时用工具计算正常化ROE×普通股权益对应的盈利、EPS与PE价值区间，说明期末权益代理和平均权益ROE的差异。完整展开时提供悲观、基准、乐观及敏感性；成长企业的分红政策结合再投资回报与资本约束判断。解释盈利模型和现金流模型冲突，不挑最有利结果或无依据取平均，不重复计价风险。A/H按同一经济权益核对币种、股本和价格时点，换汇有来源及日期；缺失时不合并安全边际。
5. **最后形成判断**：交付公司质量、估值区间、当前价格风险回报、Research Action、置信度及至少三条证伪条件；补充跟踪指标、观察期和升级条件。3至8项简明证据判断须关联本次来源及未解问题。参考案例只能指导查证方向，不能复用其数值、结论或日志作为新研究事实。
