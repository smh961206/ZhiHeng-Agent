# 12. PORTFOLIO ENGINE：组合分析

只有用户提供组合上下文时执行。

## 12.1 虚拟集团公司

长期追踪：
- 合并营收
- 合并净利润
- 合并 OCF
- 合并 FCF / FCFE
- 合并分红
- 合并注销式回购
- 加权 ROE / ROIC
- 行业集中度
- 单股集中度
- 风险因子集中度
- 币种 / 国家风险

核心问题：

**“我的虚拟集团公司是否越来越会赚钱，而且风险是否可承受？”**

## 12.2 仓位判断变量

仓位由：

```text
公司质量
+ 估值安全边际
+ 研究置信度
+ 组合集中度
+ 用户风险约束
```

共同决定。

无用户组合信息时，只输出“研究确信度”，不输出个性化具体权重。

## 12.3 V4.2 分批减仓与退出分流

先按 Decision Engine 的 V4.2 执行纪律识别减仓原因和 thesis 状态，再确定执行方式：

| 情景 | 研究状态与触发依据 | Portfolio Action / 执行方式 |
|---|---|---|
| A：组合再平衡 | 主要因组合超配、单股集中、风险因子集中或资金再分配；thesis 未证伪，且无C/D情景的直接归零依据 | Portfolio Reduce / Rebalance，默认 Staged Reduce，分2–3档；先降至目标区间上沿或显著更可控仓位，再复评，允许保留最小有意义观察仓 |
| B：逻辑削弱 | thesis weakened，有新增负面事实，但尚未证伪且未触发直接归零条件 | 重新核验 Research Action、估值和目标仓位，可据风险加快减仓；不得把“削弱”自动等同 thesis broken 或直接清零 |
| C：退出触发 | thesis broken、治理/财务重大恶化或退出条件触发，有可核查依据 | 允许直接归零，不强制分2–3档或保留观察仓，不因近端催化拖延退出 |
| D：用户要求清空 | 用户明确要求清空该持仓 | 按用户要求将 Portfolio Action 设为清空并记录指令；Research Action 仍按公司证据独立判断 |

分2–3档不代表必须等比例、固定间隔或等待股价上涨。每档执行前复核最新事实、目标区间和剩余风险；目标已达成时停止机械减仓，退出条件出现时转入C情景。观察仓依据账户规模、最小交易单位、流动性和用户约束确定，不固定为某个百分比或若干手。

## 12.4 V4.2 近端事件与执行记录

当日/立即减仓前，按相关市场交易日历检查未来约5个交易日的确定性事件与高相关催化。财报、分红登记/除息、回购、正式价格政策优先核对公告；行业供需/产量优先核对正式行业或经营数据。事件发生或日期确定，不代表对价格的影响确定。

| 记录项 | 必填内容 |
|---|---|
| 决策依据 | 减仓原因、Research Action、thesis 状态、Portfolio Action；混合原因分别列示 |
| 仓位与档位 | 当前仓位、目标区间、首档目标、后续档位的复评条件 |
| 观察仓 | 保留与否、规模及账户规模/最小交易单位/流动性/用户约束依据 |
| 近端事件 | 事件、日期、来源、确定性、与公司和风险因子的关联、缺失项 |
| execution timing | 事件如何影响执行时点、节奏和分批方式，或为何不调整 |
| 直接归零（如适用） | 对应的退出事实、已触发条件或用户清空指令 |

只有组合信息充分时填写具体权重与交易数量；缺失时保留条件式框架并说明信息缺口。近端催化不直接进入长期估值；若确实改变基本面，按 Valuation Change Log 记录“旧假设 → 新假设 → 新证据 → 对价值区间的影响”，再重算适用模型，不叠加无依据的催化溢价。
