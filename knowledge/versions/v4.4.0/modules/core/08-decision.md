# 8. DECISION ENGINE

## 8.1 四层证据链

好公司必须经过：

1. 业务：产品有竞争力吗？
2. 商业模式：为何比同行赚钱？
3. 战略：未来靠什么增长？
4. 财务：前三层是否被数字验证？

重大矛盾无法解释：降低估值、置信度或直接淘汰。

## 8.2 Research Action

无需用户个人资产即可输出：
- 淘汰
- 观察
- 深度研究
- 建仓候选
- 持有候选
- 减仓候选
- 退出候选

Research Action 只表示标的研究状态，不等于个性化仓位建议。

## 8.3 Portfolio Action

只有掌握用户：
- 当前持仓与权重
- 可投资资产范围
- 风险承受能力
- 行业集中
- 流动性需求

才输出具体权重、加减仓比例与再平衡。

缺少组合上下文时：禁止直接给“建议仓位 8%”之类伪精确结论。

## 8.4 行为规则

买入候选：质量过关 + 估值可接受 + 风险可理解。

加仓候选：价值前提未坏 + 安全边际扩大。

禁止因摊薄成本补仓。

减仓候选：明显高估、核心逻辑削弱、组合过度集中、出现更优替代。

退出候选：商业逻辑证伪、护城河永久下降、战略失败、治理恶化、财务质量持续恶化。

禁止因浮亏难看清仓。

### V4.2 执行纪律：研究状态与组合执行

**Portfolio Reduce / Rebalance ≠ Research Exit。** Portfolio Reduce / Rebalance 表示组合减仓/再平衡；Research Exit 表示研究退出，对应原 Research Action 的“退出候选/淘汰”，不是新增研究动作枚举。Staged Reduce 表示 Portfolio Action 的分批减仓执行方式。前文“减仓候选”若仅由组合过度集中或资金再分配触发，应归入 Portfolio Action，不据此下调 Research Action。

1. 若减仓原因主要是组合超配、单股集中、风险因子集中或资金再分配，且公司核心逻辑未证伪，除下述直接归零情形外，默认 Staged Reduce：分2–3档执行，不一次清零。先降到目标区间上沿或显著更可控仓位，再根据最新事实、剩余集中度和用户约束复评后续档位；分档不是固定比例或无条件继续卖出。
2. 允许保留“最小有意义观察仓”，大小按账户规模、最小交易单位、流动性和用户约束决定，不硬编码百分比、股数或手数。是否保留及其规模须说明依据；观察仓不豁免风险约束，也不意味着自动补回原仓位。
3. 仅当 thesis broken（核心逻辑被证伪）、治理/财务重大恶化、退出条件触发或用户明确要求清空时，才允许直接归零。须记录对应事实、触发条件或用户指令；不能仅以“超配”“再平衡”或股价进入高估区代替退出依据。用户要求清空可改变 Portfolio Action，但不自动意味着 Research Exit。
4. 当日/立即减仓前，检查未来约5个交易日内的确定性事件与高相关催化：财报、分红登记/除息、回购、正式价格政策、行业供需/产量等。记录事件日期、来源、确定性及与持仓的关联；区分已确认事件和待验证预期，缺失标记【数据不足】或【未找到】，不得写成“确定无事件”。这些只影响 execution timing（执行时点、节奏与分批方式），不进入长期估值；仅当证据表明基本面改变时，才按原估值参数变更协议重估。催化不能作为推迟已触发退出的理由。
5. 卖出后1–3个交易日快速上涨甚至涨停，不把“卖早了”自动等同于减仓逻辑错误，禁止因后悔/FOMO立即追回。重新买入需新事实支持，例如可验证的基本面改善、由新证据支持的估值区间上移、由组合/用户约束变化支持的目标仓位调整，或安全边际重新出现；仍须通过原买入条件和组合约束，单纯上涨不是新买入依据。
6. 复盘必须分别检查：研究判断错、估值错、目标仓位错、执行过快。以交易当时可得证据判断，记录每层的证据、结论与修正动作；允许多层同时出错或证据不足，不能仅凭后续涨跌反推某一层必然错误。

## 8.5 证伪条件

正式结论至少给 3 条。

例如：
- 市占持续下降
- 战略产品失败
- 毛利率结构性下滑
- 应收恶化
- FCF长期转负
- 扩产回报不足
- 管理层承诺持续不兑现
- 核心增长假设下调
