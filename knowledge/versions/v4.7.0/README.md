# V4.7.0 快照更新与实际读取追溯

基于 V4.6 完成剩余加载优化。一个入口、一份目录、36 个专项文件；全部业务正文与 V4.6 逐字节一致，公式、评分、判断条件和第 7 版交付协议不变。

| 优化 | 行为 |
| --- | --- |
| 新任务采用更新 | 同一执行框架版本内，新任务创建前检查入口、目录、全部文件校验值、章节索引及必需路由；通过后才绑定新快照 |
| 更新失败回退 | 写入未完成、索引损坏或框架版本不兼容时，继续使用最近有效快照，并显示更新尚未通过校验的提示；没有任何有效快照时阻止运行 |
| 任务固定版本 | 创建后的任务始终从不可覆盖的自动快照按需读取，更新后首次读取的模块也来自原快照，避免草稿与审计混用版本 |
| 中断恢复 | 保存快照编号与来源摘要；重启后可恢复原快照。缺少快照的旧记录仍核对当前规则，规则改变或原快照不可验证时重新研究 |
| 实际读取记录 | 区分文件打开与送入上下文的小节，保存触发原因、路径、行号、文件及实际内容 SHA-256、截断标记和快照编号；重复记录去重 |
| 记录保存与查阅 | 读取记录随任务状态、执行进度保存及最终报告保留；执行轨迹中的“查看规则来源”可展开核对 |

完整来源目录继续保留用于追溯，但不表示任务已经使用全部内容。接纳快照时的全量完整性校验也不记作模型已经阅读全库。文件读取缓存按任务隔离，未选中的章节不注入提示。Quick / Standard / Deep、执行输出与作战图的加载边界沿用 V4.6。

本次更新需要部署新后端程序；后续同一框架版本的知识文件修订无需重启。跨框架版本、路由程序或交付协议的变更仍需同步部署，知识热更新不会代替程序升级。

验证覆盖：有效更新切换、编辑中回退、重启恢复、首次延迟读取仍固定旧文件、目录损坏拒绝、快照篡改拒绝、实际读取及截断校验、模型工具补读到审计报告的完整流程。使用本地合成资料和模拟模型接口，不调用真实研究或交易。

发布文件包含 ENTRY.md、modules.json、全部 36 个专项及本说明，字节数与校验值记录在 manifest.json；本目录不得覆盖。
